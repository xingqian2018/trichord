# Arena 用户 Prompt 分析（cosmos3-super-t2i-agentic）

日期：2026-10-14

## TL;DR

- 共有 **19.1 万条** arena 用户 prompt，时间范围是 2026-06-26 到 2026-09-17。精确去重后剩 **16.6 万条**。
- 人工抽查 100 条随机样本，发现约 **28% 不是能单独拿来出图的 T2I prompt**，其中：
  - 续改或编辑：约 17%。
  - 闲聊或垃圾：约 7%。
  - 视频请求：约 4%。

  做 taxonomy 或构建 benchmark 时，必须先把这部分过滤掉。
- 有效 T2I 中最大的一类是**平面设计和带文字的商业图**，约 35%，包括 logo、海报、社媒封面、邀请函、标签、信息图等。其次是人物（约 20%）和角色/IP（约 14%）。
- 56% 的 prompt 被 agent 解析出了需要渲染的文字元素，所以**文字渲染是 arena 用户最主要的需求之一**，而且常常是非英文的长段文字。
- 非英文 prompt 约占 1/3：俄语和乌克兰语 17.5%，阿拉伯语和波斯语 8.7%，中文 4.3%。
- 擦边、恋物、绕过审核的 prompt 比例不低，人工抽样估计约 8–10%，需要单独作为一类。

### 2.5 Agentic 生成质量

- 有 `best_score` 的记录只有 90,059 条（47%），其余 101,086 条没有分数，可能是 judge 失败或者没有运行，原因还要另查。
- 在有分数的记录里：
  - 平均分 7.72。
  - 分数分布：8 分 35%，9 分 26%，7 分 19%，6 分及以下 16%。
- 达到阈值（`threshold_cleared_any`）的记录占全体的 13.1%。
- 最佳结果出现在哪一轮：第 0 轮 69%，第 1 轮 16%，第 2 轮 15%。也就是说，多数 prompt 的多轮改写没有带来提升。

## 3. 人工抽样分析（100 条均匀随机样本）

全部 prompt 目录打乱顺序后下载，取最先返回的 100 条作为样本，覆盖了 06-26 到 09-16 各个时间段。样本量为 100 时，比例的误差大约是 ±9%，所以只适合用来确定框架，具体比例需要后续大样本打标确认。

### 3.1 第一层：请求类型

| 类型 | 条数 | 典型例子 |
|---|---|---|
| 可以单独出图的 T2I | ~72 | — |
| 续改或编辑（依赖上一张图或参考图） | ~17 | "I choose a, but put my name on the top left"、"keep everything same in A image just aspect ratio to 9:16"、"Переделай платье в раздельный купальник"、"重新生成" |
| 不是出图请求（闲聊、问问题、写邮件、广告、粘贴的 LLM 回复） | ~7 | "????"、"سلام"、帮忙写正式邮件、"Chatgpt Free Premium Access 🤯"、整段 gpt-5.5 的回复 |
| 视频或分镜请求 | ~4 | "Create a 10-second cinematic comedy video continuing from the previous episode"、多镜头的 Cinematic sequence |

续改类最多。原因是 arena 是多轮对话，但数据里只存了单条用户文本，上下文和参考图都丢了，这类 prompt 不能直接拿来做 T2I 评测。

## 4. 建议的 Taxonomy

```
L0 请求类型
├── T2I（可以单独出图）
├── 续改 / 编辑（依赖上下文或参考图）
├── 视频 / 分镜
└── 非图像请求（闲聊、问答、垃圾、广告）

L1 内容领域（只针对 T2I）
├── 平面设计 / 商业
│   ├── logo / 图标
│   ├── 海报 / flyer / banner
│   ├── 社媒素材 / 封面 / 模板
│   └── 邀请函 / 标签 / 信息图 / UI
├── 人物
│   ├── 写实人像 / 时尚
│   ├── 生活 / 叙事场景
│   └── 名人
├── 角色 / IP
│   ├── 动漫 / 游戏 / 卡通同人
│   └── 原创角色设计
├── 物体 / 美食 / 产品
├── 场景（风景 / 建筑 / 室内 / 活动）
├── 动物
└── 图案 / 纹理 / 抽象

L2 风格：写实摄影 / 插画·矢量 / 动漫 / 3D / 绘画

标签：要渲染文字（以及文字语言）、擦边 / 违规、名人 / IP、指定宽高比
```

人工抽查的 100 条都能明确归入这个框架，没有找到放不下的。

## 5. 局限

- 第 3 节的比例来自 100 条样本，误差大约 ±9%，只用来确定框架。
- 第 2.4 节的关键词统计受多语言覆盖不全的影响，只能当下限参考。
- 一半以上的记录没有 judge 分数，所以第 2.5 节的质量统计只能代表有分数的那部分记录。
- 数据里只有单条用户文本，看不到多轮上下文和用户上传的参考图。

## 6. 下一步

1. **大样本 LLM 打标**：随机抽约 2,000 条，按第 4 节的定义交给 gemini-3.8-flash 打标，每次 50 条，共约 40 次调用，总花费不到 1M token。这样比例的误差可以缩小到 ±2% 左右。
2. **一致性校验**：从中取 300 条，用 gemini-3.1-pro 再标一遍，计算各层的一致率；一致率低的类别，修改定义后重新打标。
3. **查明缺失原因**：46,707 个目录没有 manifest，10.1 万条记录没有分数，需要确认是 pipeline 失败还是有意跳过。
4. **构建 benchmark**：根据 L0 过滤，只保留 T2I；按 L1 和文字标签分层采样；同一用户刷屏的 prompt（同一模板换关键词）需要限制数量。
