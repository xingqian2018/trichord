# Cosmos3.5 60B/30B-A3B：生成塔 MoE 在 UGB 上的路由统计

统计未经 SFT 的 Cosmos3.5 base checkpoint 在生成全部 1170 条 UniGenBench prompt 时，生成塔（`mlp_moe_gen`）每一层 MoE 的路由情况。目的是弄清生成塔的路由器实际在多大程度上“在路由”，为 exp004 的消融实验（生成塔 GQA → MHA、MoE → 同等激活宽度的 dense）提供依据。

## 结论摘要

1. **负载集中是模型本身的性质，不是 prompt 样本的偶然。** 用前 10 条 prompt 和用全部 1170 条 prompt 算出的每层有效专家数，跨层相关系数 0.996。第 0–6 层和第 25–47 层接近均衡（128 个专家中有效专家 104–123 个）；第 7–24 层明显集中（38–96 个）。第 7 层最极端：6 个专家承担了一半负载，50 个专家的负载不到平均水平的 10%。
2. **路由分数几乎不区分专家。** 每层每个 token 的平均路由熵在 4.74–4.85 nats，而 128 个专家均匀分布时的上限是 ln 128 = 4.85；每个专家的路由概率总量与它实际分到的 token 数也基本不相关（−0.29 到 +0.13）。所以一个 token 被分给哪 8 个专家，主要由 aux-loss-free 的选择偏置（`expert_bias`）加上路由分数间的微小差异决定，而不是由一个“有把握”的路由器决定。
3. **第 0–24 层对每张图的路由几乎一样；第 26–47 层按图片内容路由。** 第 6–19 层每张图的专家负载分布和 1170 张图的总体几乎一致（JS 散度中位数 0.002–0.008；单张图负载最重的 8 个专家里有 7–8 个就是总体最重的 8 个）。第 26–47 层不同图之间差异明显（JS 0.017–0.049，最重的 8 个专家只重合 3–4 个，单张图的有效专家数比总体少 8–21 个）。
4. **对 exp004_002（MoE → dense）的意义：** 在路由与输入基本无关的第 0–24 层，换成固定的 dense FFN 损失很小；主要损失的是第 26–47 层按内容路由的能力。

| 单图有效专家数 | 单张图内部的有效专家数（取中位数） |

## 分析

### 1. 第 7–24 层的集中在不同 prompt 之间很稳定

10 条 prompt 就能复现 1170 条的结果（第 7 层：有效专家 37.9 vs 37.7；第 18 层：55.8 vs 55.9）。而且在第 6–19 层，单张图的负载分布和整个 benchmark 几乎一样。在这个文生图任务上，这几层的集中是固定的性质。

### 2. 每个 token 的路由概率都接近均匀

每个 token 的路由熵在 4.74–4.85 nats，上限是 4.85，说明每个 token 自己的归一化路由分数在 128 个专家上就接近平的，不只是累加之后才平。一个专家的路由概率总量也预测不了它实际分到多少 token（相关系数 −0.29 到 +0.13；第 26–46 层大多略为负相关）。实际选出的 top-8 是按“分数 + `expert_bias`”取的；分数几乎是平的，所以起决定作用的是偏置和分数间的微小差异。

这是从统计量得出的推断，`expert_bias` 本身的数值还没有看（见“下一步”）。

### 3. 只有后段层在按内容路由

第 26–47 层总体是均衡的，但单张图并不均衡：一张图用到的专家比整个 benchmark 少（例如第 30 层 95.5 vs 116.4），不同的图偏好不同的专家（单图最重的 8 个专家里只有 3 个是总体最重的）。只有在这一段，路由器才像一个按内容做选择的路由器。

## 对 exp004 的意义

| 实验 | 生成塔 | 与本报告的关系 |
|---|---|---|
| exp004_000 | GQA + MoE（对照组） | — |
| exp004_001 | MHA + MoE | 初始化时路由不变（MHA 转换是精确的） |
| exp004_002 | MHA + dense，宽 6912 = 8 × 768 路由部分 + 768 共享专家，专家按编号每 16 个一组合并 | 第 0–24 层的路由基本与输入无关，换成固定 dense FFN 损失不大；第 26–47 层会失去按内容路由的能力 |

- 按校准统计合并（按共同激活把专家分组，组内和组间都按实际负载加权）在第 7–24 层最有意义，因为这几层的负载稳定地集中在一小批专家上；在均衡的层，不管怎么分组都相当于对很多专家取平均。在前 10 条 prompt 的统计上，按共同激活分组把“组内两两共同激活亲和度占比”从 0.123（按编号分组，接近随机的 0.118）提高到 0.201，提升有限，因为专家之间的共同激活本身比较分散。
- 如果组的缩放系数按负载比例设，集中层里有些组一开始几乎是关掉的（第 18 层在 10 条统计上为 0.002–0.53）。要不要给缩放系数设下限，还没定。

## 局限

- 只测了一种任务：文生图，960×960，UGB prompt。视频、其他分辨率、训练数据的分布都没有测。
- 50 个去噪步和两个 CFG 分支是加在一起统计的。第 0–24 层的路由与图片无关，但仍可能和时间步有关，这里区分不了。
- 只测了未经 SFT 的 checkpoint 的 EMA 权重。SFT 之后（exp003 / exp004）路由可能不同；推理时 `expert_bias` 不更新，保持 checkpoint 里的值。
- 第 2 点把原因归到 `expert_bias` 是推断，没有直接测量。

## 下一步

1. 从 checkpoint 读出每层的 `expert_bias`，和路由 logit 的差异幅度比较，确认实际分配是由偏置决定的。
2. 按去噪步拆分统计，看第 0–24 层的路由是否随时间步变化。
3. 等 exp004_000 / exp004_001 训练后，用同样方法再测一次，看 SFT 有没有改变路由。
4. 用 1170 条的统计生成按校准统计合并的 dense checkpoint（`iter_000741260_gen_mha32_dense8_calib`），与 exp004_002 的按编号合并对比。
