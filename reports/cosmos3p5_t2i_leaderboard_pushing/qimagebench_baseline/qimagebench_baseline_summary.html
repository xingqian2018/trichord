1. 怎么算分

判分模型是 Q-Judger。它对着检查表给每张图逐项打 0、1、2，换算成 0、60、100 分后，从 L3 小项到总分一层层取平均。判分协议照搬 Qwen-Image-Bench 官方代码，只改了大图的缩放方式；prompt 集和每条 prompt 考哪些维度是我们自己定的。

  1. 定维度：每条 prompt 有一个 dims 字段，列出要考的 L1。Quality、Aesthetics、Alignment 每条都考；Real-world Fidelity（RWF）和 Creative Generation（CG）只考标注过的 prompt，标注方法见第 4 节。
  2. 调 judge：每张图的每个 L1 调一次 judge。输入是原版英文 prompt、图、L1 名称、计分档位说明，以及这个 L1 的整张检查表。judge 先思考，再输出 JSON，给表里每个 L3 打 0、1、2 或 N/A。
  3. 换算：0 记 0 分，1 记 60 分，2 记 100 分，N/A 不计入。
  4. 层层平均：按下面的式子从 L3 平均到总分。L3 全是 N/A 的 L2 不参与；子集的每个 L1、L2 只在有这一项分数的图上平均。arena1000_ocr 和 arena1000_noocr 是 arena1000 的拆分，按同样方式在各自的图上算，不另外进总分。
L2 = mean(这个 L2 下不是 N/A 的 L3)
L1 = mean(这个 L1 下的 L2)
单图总分 = mean(这张图考到的 L1，3 到 5 个)
子集总分 = mean(子集内各图的单图总分)
QImageBench 总分 = (arena1000 总分 + cosmos500 总分) / 2
L1 和 L2 的 QImageBench 分同样是两个子集等权平均

读分时注意

  • 每项都是 Pass 时正好 60 分。任何一层的分数高于 60，说明有 Excel 项；低于 60，说明有 Fail 项。15 组的总分在 51 到 63 之间，差别主要看 Fail 和 Excel 各有多少。
  • 总分不是 5 个 L1 的简单平均。每张图只平均自己考到的 L1，而 RWF、CG 只在部分图上考。比如 GPT-image-2.5 的总分是 62.53，把 5 个 L1 直接平均是 63.14。
  • 各列背后的图数不一样。RWF 只来自 886 张图，CG 只来自 802 张；L2 还要再去掉 judge 判为 N/A 的图。

4. 哪些 prompt 考 RWF 和 CG

官方数据集的每条 prompt 自带要考的维度。我们的 prompt 是自己写的，没有这个标签，所以仿照官方的做法，先挑 L3 再推出 L1，用三个模型来标：opus-5.5、kimi-k3、gpt-6-astra。每个模型只看 prompt，从 56 个 L3 里挑出这条 prompt 真正在考的 3 到 10 项。

  • RWF：只要有一个模型挑了 RWF 下的项，这条 prompt 就考 RWF。
  • CG：至少两个模型挑了 CG 下的项，才考 CG。
  • 校准：这两条规则是在官方 1000 条 prompt 上定的，奇数 ID 用来调规则，偶数 ID 留作 held-out，只评一次。held-out 上 RWF 标为要考的比例是 51.6%（官方 45.8%），和官方标签的 kappa 是 0.430；CG 是 64.8%（官方 62.8%），kappa 0.593。RWF 的 kappa 上限大约在 0.45 到 0.52，因为官方标签本身就稀疏、不太一致。

5. Prompt 集

  • arena1000：1000 条，按 arena 分类体系（t2i_arena_v0）的权重分层抽题，再由几个写作模型轮流写成英文 prompt。其中 350 条要求图里出现可读文字（ocr 为真），组成 arena1000_ocr；其余 650 条是 arena1000_noocr。
  • cosmos500：500 条，按 Cosmos 分类体系（t2i_cosmos_v0）里各大类的比例抽题，写法同上，没有 ocr 拆分。
  • prompt 的目标长度取官方英文 prompt 词数的分位数，长度分布贴近官方；写完后，近似重复的 prompt 会被改写。
  • 2026-11-07 做过一次真人和版权 IP 筛查：arena1000 里点名真人或版权角色的 58 条，在类别不变的前提下改写成虚构的人物和作品，并用同样的方法重标了维度；cosmos500 没有命中。
  • 15 组结果打分用的是同一版 prompt，结果文件里记录的 prompt 集哈希都一样。

6. Judge 设置与失败处理

  • 模型：Q-Judger（Qwen/Qwen-Image-Bench），在 Qwen3.6-27B 上微调，出自 Qwen-Image-Bench（EMNLP 2026，arXiv 2605.28091）。部署在 Lepton 上（endpoint scorer-qimagebench，vLLM，bf16），RL 用的也是这个服务。
  • 采样：开 thinking，greedy 解码：temperature 0、top_k 1、top_p 1.0、repetition_penalty 1.05、max_tokens 4096、seed 42。
  • 图像：面积不超过 1024×1024 的图原样送；更大的按原比例缩到 1024×1024 的面积。所以 Qwen-Image 2.1 和 Ideogram 4 的 2048² 图会先缩到 1024²，其余模型的 1024² 图原样送；cosmos3 16:9 和 mix7 的各个尺寸面积也都不超过 1024²，原样送。官方 judge.py 会把任一边超过 1024 的图直接压成 1024×1024；对方图来说两种做法一样。
  • prompt：judge 看到的是原版英文 prompt，不是各模型生成时用的改写版。
  • 解析：只取 judge 输出里 </think> 之后的 JSON。如果某个 L3 被放到了错的 L2 下，按官方的对应关系挪回去。
  • 解析失败：某个 L1 的输出解析不出来时，这张图标为 failed，这个 L1 不计入，不记 0 分；这张图的其他 L1 照常计入。做法和官方 scorer 一致。
  • 请求失败：超时、返回格式不对或读图失败的请求会重试，每张图最多试 3 次。
  • 本报告：15 组都是 1500/1500 张出分。解析失败一共 5 次，都出在 Quality：cosmos3-super-text2image 1:1 2 张、mix7 1 张，cosmos3-x9c 1 张，Nano Banana 2.1 1 张；16:9 和 mix7→1:1 没有。cosmos3.5-ultra 四组打分时，解析失败的图也会重试，最后都是 0 张 failed。

7. 能不能和官方榜单比

不能直接比。检查表、judge prompt、采样参数、解析和平均方式都照搬官方代码：把官方数据集里存的 Q-Judger 原始输出交给我们的解析和汇总代码，能完全复现官方 README 的榜单，比如 GPT Image 2 的总分 64.69。但 prompt 集和每条 prompt 考哪些维度是我们自己定的，所以本报告的分数只适合在这 11 组之间比。

1. 问题

换了出图比例，同一条 prompt 的单图分数会变多少？judge 对非方图打分可信吗？对象是 cosmos3-super-text2image（exp009_sft0_uhq_iter31k）：拿 mix7 里每张图的单图总分，减去 1:1 那组同一条 prompt 的单图总分，记为 Δ。

  • judge 的输入没有变形。我们的预处理在面积超过 1024² 时按原比例缩小，没超过就原样送；vLLM 端用 Q-Judger 自带的处理器配置，只把边长对齐到 32。7 种尺寸实际进模型的是 1008 到 1036 个视觉 token，比例偏差不到 2%。官方 judge.py 会把最长边超过 1024 的图直接压成 1024×1024，这 6 种非方尺寸都会被压变形。
  • 但 Q-Judger 很可能没怎么见过非方图。官方 benchmark 的图全是 1024² 方图，judge 在非方图上有没有偏好，输入正确也证明不了，只能看打出来的分。

6. 结论

  • 同一张图重打一次，分数就会变。全量 1500 张重打，单图总分的标准差 3.6，最多差 27 分，Creative 最不稳（见打分波动 tab）。
  • 非方图必须保持比例送 judge。同一内容强制压成 1:1，非方图平均掉 2 到 3.4 分，扣在 Quality、RWF 和 Aesthetics 上（第 3 节）。
  • 大幅涨跌里，真实变化和 judge 噪声各占一部分。9 个非方例子里，4 个是图真的变好或变差，3 个方向对但幅度被 judge 放大，2 个基本是 judge 不稳。
  • 换比例确实会改变图。横向的主体（横轴、爆炸图、侧面的车）放进竖画幅会吃亏：主体变小、留空变多，甚至排布出错；放进横画幅则占便宜。
  • judge 最不稳的是 Aesthetics 和 Creative Generation。相近的两张图，Aesthetics 能从 30 跳到 100；Creative 往往只考一两个 L3，打分接近 100 或 0，图稍有变化整项就翻转。
  • 平均下来影响不大。涨跌两头都有，横图平均多涨 1 到 2 分。比较整套平均分还算可靠，但不要用单张图的分数判断哪个比例更好。
  • 还要做的验证：让一个对比模型也出一份 16:9。它如果也涨 2 分左右，说明是 judge 偏爱宽画幅；基本不涨，才能算 cosmos3 自己在宽画幅上更好。

1. 同一张图重打一次

把 cosmos3-super-text2image 1:1 那组的 1500 张图原样交给 judge 再打一次分（结果存为 qimagebench_result_rescore1.json，原结果不动）。judge 用 greedy 解码（temperature 0、seed 42），按理两次应该一样，实际并不一样。

每张图重打一次会差多少（Δ = 第一次 − 重打，单位：分）

每张图算一个 Δ，再统计这些 Δ 的 mean、std、min、max。

单张图的 Δ（分）：圆点是 mean，色块是 mean ± std，横线是 min 到 max

只算两次都有分的图；RWF、Creative 只在考到这一项的 prompt 上有分，所以图数少。

之前用 mix7 里分到 1:1 的 213 条 prompt 当对照（图和 1:1 那组几乎逐像素相同）估过一次，单图总分的 Δ 标准差是 4.44；同样这 213 条 prompt 在这次全量重打里是 4.05。这批 prompt 本身比平均噪一些，全量的 3.58 更有代表性。

原因很可能在推理的数值上：vLLM 在不同的 batch 组合下，浮点结果会有细微差别；judge 先写一长段 thinking，某个 token 一旦分叉，后面的结论就可能不同。这一点没有单独验证。

2. overall 分数的 std 随图数的变化

同一张图打两次，单图总分之差的 std 是 3.58。N 张图取平均后，两次 overall 之差的 std 就是 3.58 / √N。下面的曲线画的就是这个数，N 从 1 到 5000；虚线是 95% 范围（1.96 倍）。比较两个模型时，每个模型各打一次分，分差里的噪声也是这么大。

两次打分的 overall 之差：std 随图数的变化（分）

曲线按所有图等权平均算。实际的 overall 是 arena1000 和 cosmos500 等权平均，所以 1500 张时预期 std 是 0.10，比曲线上的 0.092 略大；实际差 −0.12 在 95% 范围内。

5. 怎么算分

  1. UGB（UniGenBench v2_1170L）共 1170 条 prompt，分成 orig（原始 prompt）和 phi（另一半）两个子集。每条 prompt 带若干 testpoint，每个 testpoint 属于一个 L2 类别，L2 归到 10 个 L1。
  2. judge 看图和原版 prompt，对每个 testpoint 判对或错。
  3. 准确率 = 判对的 testpoint 数 / testpoint 总数，按 testpoint 计，不是先按 prompt 平均。L1、L2 的分数都是该类 testpoint 的准确率；overall 合并两个子集的全部 testpoint。
  4. 缺图不计入分母。API 和开源模型因为安全过滤或 upsampler 失败，少了 1–5 张图（见第 1 节“出图数”），准确率只按实际打了分的样本算。
  5. 噪声参考：同一批图用 gemini-3.1-pro 和 gemini-3.1-pro@nvidia 各打一次，overall 相差 0.01–0.11。

Spearman：看每个模型的名次差了多少。把两边的分数都换成名次，按 ρ = 1 − 6·Σd² / (n(n² − 1)) 计算，d 是同一个模型在两边的名次差。例：QImageBench vs AA 的 7 个模型里，Ideogram 4 差 2 名，FLUX.3 klein 和 Fibo 2.0 各差 1 名，其余名次相同，Σd² = 4 + 1 + 1 = 6，ρ = 1 − 36 / 336 = 0.89。名次差是平方后计入的，一个模型跳很多名会扣得很多。

Kendall：数有几对模型的先后顺序反了。把模型两两配对，两边谁高谁低一致的算「同序」，相反的算「逆序」，τ = (同序 − 逆序) / 总对数。例：7 个模型共 21 对，只有「Ideogram 4 vs FLUX.3 klein」和「Ideogram 4 vs Fibo 2.0」这 2 对顺序相反，τ = (19 − 2) / 21 = 0.81，可以直接读成「21 对里有 2 对顺序反了」。

Pearson：看分数和 Elo 数值是不是成比例。不换成名次，直接算两边数值的线性相关。排序全对、但分差比例和 Elo 差得远时，Pearson 也会偏低，比如 arena1000_ocr 的 Spearman 是 0.96，Pearson 只有 0.82。

三者都在 −1 到 1 之间：1 表示完全一致，0 表示没有关系，−1 表示完全相反。这里每组只有 6 到 9 个模型，一个模型换位置，系数就会变很多。
