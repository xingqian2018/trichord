把 Q-Judger 用作真实图片过滤器

用 QImageBench 的打分模型 Q-Judger（Qwen/Qwen-Image-Bench，Qwen3.6-27B）给真实训练图片打分，代替现有的图片 filter qwen3vl_fft_8b_v1，目标是从 4000 万张里挑出约 100 万张顶级图。judge 只看图片，不看 caption，用的是"真实照片"版 prompt：每张图问 3 个维度，一共 17 项，Quality 里另外问一个不打分的是/否项 upright_orientation，标出存成横着或倒着的图。这套 prompt 是在 1000 张真实照片上逐项看图校准出来的。这是过滤器的 v0，也就是第一个版本，输出列是 filter_real_image_qjudge_v0。11-13 初稿里"judge 输入一字不改""用 caption 填 prompt""服务端不改"这三条都已推翻，原因见第 2 节。

1. 已经定下来的事

  1. 目标是从 4000 万张里挑出约 100 万张顶级图。代替现有 filter，拼接图、带大字的图、白底图不再整类丢弃，和其他图一样打分。为了挑顶级图，可以接受一定的误伤。
  2. judge 只看图片，不传 caption。system prompt 是真实照片版："You are an expert evaluator of the quality of real photographs. Given a real photograph taken by a camera, …"。图片前只有一行 # Real Photograph。
  3. 3 个维度，一共 17 项，judge 看到的清单就是这 17 项。官方其余题目都不问。第三个维度给 judge 看的名字是 "Text and Design"，返回字段里仍叫 "Creative Generation"。
  4. Quality 清单最后加一个不打分的方向项 upright_orientation。放在 ## Orientation 下，true 表示图是正的，false 表示存成了横着或倒着。它只是一个标记，没有 Fail/Pass/Excel，不算在 17 项里，也不参与任何打分汇总。给 judge 看的原文：upright_orientation: Is the photograph upright, i.e. not rotated sideways or upside down (e.g., the horizon is horizontal, people and buildings stand upright)? This item is not scored: instead of a score, answer {"value": true} if the image is upright, otherwise {"value": false}.
  5. 能用官方原文就用原文。改措辞只为三件事：去掉对 prompt 的依赖、去掉"AI 生成图"的定性、加上"不适用就 N/A"。Noise 保持官方原文；Text Accuracy 保留"拼写错误"条款；Feature Matching 保留。
  6. 采样参数和图片预处理和官方一致。temperature 0、top_p 1、top_k 1、repetition_penalty 1.05、max_tokens 4096、seed 42，开启 thinking。图片面积超过 1024×1024 时按原比例缩到这个面积（LANCZOS），否则原样送入。
  7. 打分的所有细节都在服务端。调用方每张图只发一个请求（prompt 加图片），拿回一个分数字典。服务端负责调 3 次 judge、解析、失败重试。调用方不能改 system prompt，也不能选维度。
  8. 所有实现共用一套 judge 输入。通用部分（官方模板、图片预处理、JSON 提取、分数映射、采样参数）继承或引用 qimagebench_protocol，不拷贝代码。

2. 和 11-13 初稿相比改了什么

初稿现在原因
judge 输入一字不改真实照片版 system prompt；清单只留计入的 17 项，其中 11 项改了措辞官方 prompt 把图定性为"生成图"，judge 会在真实照片上编造 AI 缺陷。在 10 万张测试表上已打完的约 7000 张里，Physical Logic 有 46% 判 0。随机抽 16 张判 0 的图看，都是正常照片：草挡住腿、浅景深虚化、手指贴着下巴，被读成了"融合畸形"
用图片的 caption 填 prompt不传 caption小样本上，去掉 caption 后误判同样消掉，而且对真缺陷更敏感。原来依赖 prompt 的 Composition 和 Lighting & Atmosphere 改成了不依赖 prompt 的措辞，所以不再需要准确的 caption
服务端不改，过滤逻辑放在客户端打分细节全在服务端调用方只发 prompt 和图片、收分数；不把 system prompt 和维度暴露给调用方
扔掉的 15 项照样会被问，结果不存不再问judge 只看到计入的 17 项，清单更短
不检查图片方向Quality 调用里加不打分的 upright_orientation存成转了 90° 的图是已知的数据错误，现有的 17 项抓不稳（见第 6 节）

3. 和现有 filter 的关系

现有的 filter 是 qwen3vl_fft_8b_v1（微调过的 Qwen3-VL 8B）。它给每张图打一个 0–10 的美学分和五个是/否标记，默认只留"美学分 ≥ 4 且五个标记都为否"的图。

现有 filter 的列现在怎么用新方案怎么处理
aesthetic_score≥ 4 才留由 Quality 和 Aesthetics 的逐项分数代替
text_banner为是就丢不丢。用 Text Accuracy、Text Layout、Graphic Design 评它做得好不好
white_background为是就丢不丢。用 Product Design 加 Quality、Aesthetics 来评
collage为是就丢不丢。没有专门评拼接图的题。改写后的 Feature Matching 抓的是抠图和贴图的接缝，不是多图拼版。这是缺口
watermark为是就丢Text Accuracy 的例子里写了水印，但它评的是字清不清楚，不是有没有水印。这是缺口，怎么办还没定
nsfw为是就丢Safety & Compliance 在不问的 Real-world Fidelity 里。怎么办还没定

4. 题目树

Q-Judger 一共 56 个 L3 题目，分属 5 个 L1。这里只问其中 17 项，分在 3 次调用里。每项标的是给 judge 看的措辞和官方相比有没有改；判 0 比例来自 1000 张真实照片（官方 prompt → 定稿）。

Feature Matching
Feature Matching改写官方问"多元素融合处是否无缝"，改成"主体和背景、相互接触的物体交界处是否自然，有没有抠图边、光晕、贴上去的元素"。判 0 为 1.8%，包括看图确认过的合成图和数字绘画。不太稳定：只改维度名，判 0 的图就大半对不上
Text Rendering
Text Accuracy改写举的例子换成真实场景里的字（招牌、标签、包装、说明文字、水印），没字就 N/A，保留"拼写错误"条款。真实照片判 0：4.5% → 0.4%。生成图乱码对照：官方判 0 的图里抓到 61%

Graphic Design改写图本身是或明显包含海报、广告、封面才评，否则 N/A
Product Design改写工业产品是主体才评，否则 N/A。用来评白底商品图
Spatial Design改写室内或建筑是主体才评，否则 N/A
Game Design改写有游戏道具或游戏 UI 才评，否则 N/A
不问的 39 项不问
  • Alignment（16 项）：13 项问图是否符合 prompt，没有 caption 就没法判；剩下 3 项不值得为它们多调用一次。
  • Real-world Fidelity（8 项）：Social Bias 和 Cultural Fairness 评的是生成模型的偏见，用来过滤会删掉正常照片；World Knowledge 几项在真实照片上预计恒定，或者依赖 prompt；Safety & Compliance 有效，但不值得单独多调用一次。
  • Aesthetics 里的 2 项：Emotional Expression、Style Control，问的是 prompt 描述的情绪和风格。
  • Creative Generation 里的 13 项：Imagination、Logical Resolution（评创意组合和因果关系，对真实照片不适用）；Font、Cross-lingual Generation、Fashion Styling、Art Design 和 Visual Storytelling 的 7 项（都要对照 prompt 才能判）。

另外，评分规则里 N/A 的说明从"不适用于这张图或 prompt"改成了"不适用于这张图"。

5. 输出和解析

  • 返回结构。每张图一个 {L1: {L2: {L3: 分数}}} 字典，三个 L1 键是 Quality、Aesthetics、Creative Generation，一共 17 个 L3。分数 0 / 60 / 100 对应 Fail / Pass / Excel，N/A 记为空值。
  • 方向标记。Quality.Orientation.upright_orientation 取值 true、false 或空值。judge 没回答 true/false（测试里 150 次有 2 次答了 "N/A"），或者 Quality 整个没解析出来，就记为空值。解析时读 {"value": …}，也接受 {"score": …}、字符串 "true"/"false"，以及直接写在 Orientation 下面的写法。缺了这一项不影响 Quality 其他分数。
  • 解析不依赖输出格式。judge 的 JSON 不总是标准嵌套，也会出现平铺的 L3、平铺的 L2、外面多包一层 L1，或者混着用。服务端递归找出所有带 score 的对象，按名字归位：只含一个 L3 的 L2 名（比如 Lighting）映射到那个 L3，Feature Mapping 改名为 Feature Matching。用官方 prompt 的 11,406 份历史输出做回归，结果和原来的解析完全一致。
  • 失败重试。某个维度解析不出来，只把那一次调用重跑，最多 2 次。还不行，这个维度的所有项记为空值，表示未知，不当通过也不当失败。
  • 不在打分步骤里设阈值。以后改规则不需要重新打分。

6. 校准结果

校准用的 1000 张真实照片，是从 10 万张测试表（Aesthetic-Train-V2_slice_from_maintable_20261009.lance）里已用官方 prompt 打过分的约 7000 张中随机抽的。下表是同一批图在官方 prompt 和定稿下的判 0 比例；结论是看图和 judge 的思考过程后得出的。

项目官方 prompt定稿看图后的结论

Naturalness14.1%3.9%符合定义，略偏严

Text Accuracy4.5%0.4%原来多是招牌、耳标、logo 上的正常小字
Noise0.9%约 3.5%多是夜景、胶片颗粒。改写措辞无效，接受

Design 四项—1 张几乎全是 N/A

对照组：

  • 退化图。模糊、jpeg 压缩、像素化各 10 张，Material Texture、Edge Clarity、Resolution 基本都判 0。加高斯噪声 σ=40，Noise 判 0 的有 19/20；σ=20 时有 14/20。
  • 生成图乱码。用 fibo2、flux3_klein、ideogram4 的 QImageBench 出图。官方协议判 Text Accuracy=0 的图里，定稿抓到 61%；官方判 100 的约 43 张里有 5 张判 0，其中约 3 张是背景小字确实乱码。官方协议只看 prompt 要求的那行字，这里看画面上所有的字，用来过滤正好合适。
  • 拼写条款的代价。真实照片上约 0.3% 因为现实里本来就写错的字（比如手写招牌）被判 0。

图片方向：从校准集里随机抽 50 张真实照片，每张做原图、逆时针转 90°、顺时针转 90° 三个版本。

  • 原图没有一张被误判。
  • 不加这一项时，转过的图主要靠 Composition 判 0（50 张里从 2 张升到 23 张），而这些图方向项全都抓到了。
  • 漏掉的分两类。约一半本来就没有明确的上下方向（航拍、俯拍食物、纹理），可以接受。其余是明显转了的：judge 要么没怎么推理就答了 true，要么给画面找了合理解释（侧过来的人脸被当成人躺着，鸟被当成站在"斜的树枝"上）。
  • 之前试过反过来的写法 Rotation Failure（true 表示转了），抓到 29 和 28 张；最后用正向的 upright_orientation。
  • 加了这一项，Quality 其他题的分数变化在重跑噪声以内：原图上 84% 完全一致，转过的图上 91%；不改措辞直接重跑是 83–94%。

稳定性：

  • 措辞相同的项，同一批图跑两次，分数完全一致的比例只有 83–94%，差异主要是 60 和 100 互换。
  • 拿 100（Excel）的图，两次之间只重合 40–65%。例如 Physical Logic 两次分别是 21 张和 14 张，重合 9 张。
  • "是否判 0"比具体分数稳，但处在边缘的 0 仍然会翻。

7. 怎么用来挑 100 万张

  • 975 张真实照片里，90.7% 没有任何一项判 0。只靠"去掉判 0"，只能筛掉约 9%。（这项统计做于恢复 Feature Matching 之前，当时是 16 项。）
  • 要留前 2.5%（4000 万到 100 万），还得在剩下的图里按拿 100 的项数排序：门槛大约是 16 项里至少 7 项拿 100，切线上有并列。
  • 但 Excel 不稳定，跑两次只重合 40–65%，所以单跑一次、按 Excel 项数挑前 2.5%，结果有不小的随机性。
  • 结论：Q-Judger 更适合当门槛，用来去掉判 0 的图。要在前 2.5% 里精排，需要更细的分数。一个办法是读出 judge 每一项打分的概率，算出期望分，得到连续值。还没做。

8. 风险

  • 单图噪声。Excel 跑两次只重合 40–65%，按 Excel 项数精排的随机性很大。
  • Noise 对真实颗粒偏严。约 3.5% 的真实照片因为夜景、胶片颗粒被判 0。已接受。
  • 拼写条款会误伤。现实里本来就写错的招牌约 0.3%。已接受。
  • Feature Matching 不稳定。判 0 的图在不同 prompt 版本之间重合度低，不适合单独当硬过滤条件。
  • 截断。真实照片 1.3%，字多的图 14%。截断的那个维度记为空值。
  • Anatomical Fidelity 的偏向。题目偏好看得见毛孔和细纹，可能压低修过的人像和棚拍。
  • 拼接图和水印没有对应的题。代替现有 filter 之后，这两类不会被 Q-Judger 的任何一项拦下。
  • 只在一张表上校准过。1000 张都来自 Aesthetic-Train-V2 切片表，其他来源的图没有验证过。
  • 方向项会漏判。转了 90° 的图大约抓到三分之二，有些明显转了的也会漏；测试里没有误判正常的图。只测了 50 张。

9. 还没定的问题

  • 过滤规则：门槛怎么卡，前 2.5% 怎么排。
  • 要不要做按概率算的期望分，用于精排。
  • 水印怎么办：继续用现有 filter 的 watermark 列，还是不管。
  • NSFW 怎么办：继续用现有 filter 的 nsfw 列，还是多调用一次拿 Safety & Compliance。
  • 拼接图怎么办。
