Using Q-Judger as an image filter

Q-Judger is the judge model behind QImageBench, our text-to-image benchmark. This proposal reuses it to filter real training images: each image gets a set of per-criterion grades, and a downstream rule decides whether to keep it. The aim is to replace the existing image filter: that filter drops collages, images with dominant text and white-background images as whole categories, while this one keeps the categories and uses scores to pick out the good images in them. The judge's input stays exactly as it is; criteria we do not want are skipped when we aggregate. The choices below are based on how each criterion is worded and have not been tested on real images yet.

1. Decisions already made

  1. Replace the existing filter; do not drop images by category. Collages, images with dominant text and white-background images are no longer dropped as a class. They are scored like any other image, and the high-scoring ones are kept.
  2. The judge input is not modified. The system prompt, user template, checklists and sampling parameters stay as they are in qimagebench_protocol.py. Unwanted criteria are skipped when scores are aggregated. They are not removed from the checklist or reworded.
  3. The prompt slot holds the image caption. The template requires a prompt, and with a placeholder the judge would grade "matches the prompt" criteria against nothing.
  4. Three dimensions are called for every image: Quality, Aesthetics and Creative Generation. Three calls are acceptable. The principle is to collect enough information and leave out only what does not apply at all. Alignment and Real-world Fidelity are not called.
  5. No server change. The existing scoring service already accepts a subset of dimensions and already returns a grade for every criterion.
  6. Validate before building infrastructure. We first score a 100k-image test table through the existing Lepton service. A SILA pipeline comes only after the signal proves useful.

2. How this relates to the existing filter

The production filter today is the SILA pipeline image_filter_pipeline.py (version qwen3vl_fft_8b_v1, a fine-tuned Qwen3-VL 8B). It gives each image a 0–10 aesthetic score and five yes/no flags, and by default keeps only images with an aesthetic score of at least 4 and all five flags false. So collages, images with dominant text and white-background images are dropped whether they are good or bad.

The new filter replaces it with a different approach: these categories are no longer dropped as a class. They are scored like any other image, and the high-scoring ones are kept.

This is why Creative Generation cannot simply be excluded: the criteria that say whether a poster or a product shot is well made are inside it.

4. How scores are aggregated

We do not reuse the official L3 → L2 → L1 mean, because dropping some criteria makes the L2 weights uneven.

  • Store each grade. Every counted criterion gets its own column: Fail, Pass, Excel or N/A, plus the parse status. Criteria marked "computed, discarded" are not stored.
  • Write rules on criteria. For example, "drop if Noise, Edge Clarity or Resolution is Fail". The exact rule is set after the 100k run.
  • Keep one reference score. The plain mean of the counted criteria that are not N/A, on the same 0 / 60 / 100 scale.
  • No thresholds in the scoring step. Changing a rule later must not require rescoring.
  • A parse failure is unknown. Store an empty value; never treat it as pass or fail.

6. Risks

  • Not verified on real images. Q-Judger was trained on AI-generated images. Whether the counted criteria separate good real photos from bad ones is an assumption based on their wording.
  • Single-image noise. A filter decides image by image, so the rescoring noise above applies directly. Rules should key on a clear Fail, not on a score threshold.
  • Anatomical Fidelity bias. The criterion favors skin with visible pores and fine lines and may wrongly penalize retouched and studio portraits.
  • Speed. The judge is a 27B model with thinking on. The only way to go faster is more replicas.
  • Lighting & Atmosphere depends on caption accuracy. It is the only counted criterion whose wording refers to the prompt. It cannot be used when the caption is missing, too short or wrong.
  • No criterion for collages. Q-Judger was trained on single generated images. Collages can only be graded by the general criteria, and whether those grades can be trusted depends on the validation.
  • No criterion for watermarks. Once the existing filter is replaced, no Q-Judger criterion stops a watermarked image.
  • The endpoint is shared. scorer-qimagebench also serves benchmark scoring and RL reward, so scoring jobs run one at a time, never concurrently.

7. Validation steps

Test table: s3://nv-00-10206-vfm/lancedb/image/regular/Aesthetic-Train-V2_slice_from_maintable_20261009.lance (100k rows).

  1. Inspect the table. Which columns exist, which one holds the caption, how images are fetched. Not done yet.
  2. Score a small sample. Take 500 to 2000 rows and score all three dimensions: Quality, Aesthetics and Creative Generation. Look at the Fail / Pass / Excel / N/A rate of each criterion and the parse-failure rate.
  3. Review the counted criteria. Decide whether Physical Logic and Anatomical Fidelity stay. Spot-check caption accuracy, because Lighting & Atmosphere depends on it.
  4. Compare with the existing filter. Check whether the table has the existing filter's six columns. If it does, focus on the three categories it drops (collage, dominant text, white background): can Q-Judger's scores separate the good images from the bad ones in each? Look at a batch of each by eye.
  5. Check the seven Creative Generation criteria. See whether they separate posters and product shots, and whether they are mostly N/A on ordinary photos. Also measure how much time this call actually adds.
  6. Run the full table. If the signal is useful, score all 100k images, then write the filter rule.
  7. Build SILA last. Model it on image_filter_pipeline.py and hpsv3_pipeline.py, with its own vLLM endpoint and its own copy of the protocol.

8. Open questions

  • Which column holds the caption, and how many rows have one.
  • Whether the captions in the table are accurate enough. Lighting & Atmosphere is counted on the condition that the prompt is accurate.
  • Whether any of the 15 discarded criteria (2 in Aesthetics, 13 in Creative Generation) should instead be counted with the "accurate prompt required" tag.
  • What to do about watermarks: keep using the existing filter's watermark column, or ignore them.
  • What to do about NSFW: keep using the existing filter's nsfw column, or add a Real-world Fidelity call to get Safety & Compliance.
  • Whether the grades that general criteria give to collages are usable.
  • Which production table will be filtered and how many rows it has. This sets the number of SILA replicas.
