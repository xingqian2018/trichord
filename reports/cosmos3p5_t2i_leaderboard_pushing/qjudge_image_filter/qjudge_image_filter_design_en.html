Using Q-Judger as a real-image filter

Q-Judger (Qwen/Qwen-Image-Bench, Qwen3.6-27B) is the judge model behind QImageBench. We use it to score real training images and replace the existing image filter qwen3vl_fft_8b_v1, with the goal of picking about 1M top images out of 40M. The judge sees only the image, not the caption, and gets a "real photograph" version of the prompt: 3 dimensions per image, 17 criteria in total, plus one unscored true/false item in Quality, upright_orientation, that flags images stored sideways or upside down. The prompt was calibrated criterion by criterion on 1,000 real photos, checking the images by eye. This is v0, the first version of the filter; its output column is filter_real_image_qjudge_v0. Three decisions in the 11-13 draft have been reversed: "the judge input is not modified", "the caption fills the prompt slot" and "no server change". Section 2 says why.

1. Decisions

  1. The goal is about 1M top images out of 40M. This replaces the existing filter: collages, images with dominant text and white-background images are no longer dropped as whole categories but scored like any other image. Some false rejections are acceptable when the aim is the top images.
  2. The judge sees only the image; no caption is passed. The system prompt is the real-photo version: "You are an expert evaluator of the quality of real photographs. Given a real photograph taken by a camera, …". The only text before the image is # Real Photograph.
  3. 3 dimensions, 17 criteria, and the judge's checklist is exactly these 17. No other official criterion is asked. The third dimension is shown to the judge as "Text and Design"; the returned key stays "Creative Generation".
  4. The Quality checklist ends with one unscored orientation item, upright_orientation. It sits under ## Orientation; true means the image is upright, false means it is stored sideways or upside down. It is a flag only: no Fail/Pass/Excel, not one of the 17, and never part of a score aggregate. Wording shown to the judge: upright_orientation: Is the photograph upright, i.e. not rotated sideways or upside down (e.g., the horizon is horizontal, people and buildings stand upright)? This item is not scored: instead of a score, answer {"value": true} if the image is upright, otherwise {"value": false}.
  5. Official wording wherever possible. Wording changes serve only three purposes: remove the dependence on the prompt, remove the "AI-generated image" framing, and add "answer N/A if it does not apply". Noise keeps the official wording; Text Accuracy keeps the misspelling clause; Feature Matching stays.
  6. Sampling parameters and image preprocessing match the official protocol. Temperature 0, top_p 1, top_k 1, repetition_penalty 1.05, max_tokens 4096, seed 42, thinking on. Images larger than 1024×1024 in area are scaled down to that area with the aspect ratio kept (LANCZOS); smaller ones are sent as is.
  7. All scoring details live on the server. The caller sends one request per image (prompt plus image) and gets back one score dictionary. The server makes the 3 judge calls, parses, and retries failures. The caller cannot change the system prompt or choose dimensions.
  8. Every implementation uses the same judge input. Shared parts (official template, image preprocessing, JSON extraction, score mapping, sampling parameters) are inherited from or imported from qimagebench_protocol, never copied.

3. Relation to the existing filter

The existing filter is qwen3vl_fft_8b_v1, a fine-tuned Qwen3-VL 8B. It gives each image a 0–10 aesthetic score and five yes/no flags, and by default keeps an image only if the aesthetic score is at least 4 and all five flags are no.

  • Real-world Fidelity (8): Social Bias and Cultural Fairness judge a generator's bias and would remove legitimate photos; World Knowledge criteria are expected to be constant on real photos or depend on the prompt; Safety & Compliance is valid but not worth a separate call.

5. Output and parsing

  • Return structure. One {L1: {L2: {L3: score}}} dictionary per image, with L1 keys Quality, Aesthetics and Creative Generation and 17 L3 entries. Scores 0 / 60 / 100 mean Fail / Pass / Excel; N/A is null.
  • Orientation flag. Quality.Orientation.upright_orientation is true, false or null. It is null when the judge answers anything but true/false (2 of 150 test calls answered "N/A") or when the Quality call does not parse. The parser reads {"value": …} and also accepts {"score": …}, the strings "true"/"false", and the flag written directly under Orientation. A missing flag never discards the other Quality scores.
  • Parsing does not depend on the output layout. The judge's JSON is not always properly nested: flat L3, flat L2, an extra L1 wrapper, or a mix all occur. The server collects every object that has a score, at any depth, and places it by name. An L2 name with a single L3 (for example Lighting) maps to that L3, and Feature Mapping is renamed to Feature Matching. On 11,406 past outputs from the official prompt, the result is identical to the old parser.
  • Retries. If a dimension cannot be parsed, only that call is rerun, up to 2 attempts in total. If it still fails, all criteria of that dimension are null: unknown, never treated as pass or fail.
  • No threshold in the scoring step. Changing a rule never requires rescoring.

Controls:

  • Degraded images. 10 each of blur, JPEG compression and pixelation: Material Texture, Edge Clarity and Resolution are almost always Fail. With Gaussian noise σ=40, Noise is Fail on 19/20; at σ=20, on 14/20.
  • Garbled text on generated images. QImageBench outputs of fibo2, flux3_klein and ideogram4. Of the images the official protocol grades Text Accuracy=0, the final prompt catches 61%. Of about 43 official 100s, 5 get Fail, about 3 of them with genuinely garbled background text. The official protocol checks only the text the prompt asked for; ours checks all text in the image, which is what a filter wants.
  • Cost of the misspelling clause. About 0.3% of real photos get Fail for text that is misspelled in reality (for example a hand-written market sign).

  • No original photo is flagged.
  • Without the flag, rotation shows up mainly as Composition Fail (2 to 23 of 50), and every image caught that way is also caught by the flag.
  • Misses fall in two groups. About half have no clear up direction (aerial views, top-down food, textures), which is acceptable. The rest are clearly rotated, but the judge either answered true with almost no reasoning or explained the view away (a sideways face read as a person lying down, a bird on a "diagonal branch").
  • An earlier, inverted wording, Rotation Failure (true = rotated), caught 29 and 28; the positive upright_orientation was kept.
  • Adding the item moved the other Quality scores no more than a rerun does: 84% identical on originals and 91% on rotated images, against 83-94% for an unchanged rerun.

Stability:

  • For criteria with identical wording, two runs on the same images give identical scores only 83–94% of the time, mostly 60 and 100 swapping.
  • Images graded 100 (Excel) overlap only 40–65% between two runs. Physical Logic, for example: 21 and 14 images, 9 in common.
  • "Is it a Fail" is more stable than the exact score, but borderline Fails still flip.

7. Using it to pick 1M images

  • Of 975 real photos, 90.7% have no Fail on any criterion. Dropping Fails alone removes only about 9%. (Computed before Feature Matching was restored, on 16 criteria.)
  • Keeping the top 2.5% (40M to 1M) needs a ranking of the rest by number of 100s: the cut is roughly at least 7 of 16 criteria at 100, with ties at the cut.
  • Excel is unstable, with 40–65% overlap between runs, so picking the top 2.5% by Excel count from a single run is quite random.
  • Conclusion: Q-Judger works best as a gate that removes Fails. Ranking within the top 2.5% needs a finer signal. One option is to read the judge's probability for each grade and compute an expected score, giving a continuous value. Not done yet.

8. Risks

  • Single-image noise. Excel overlaps only 40–65% between runs, so ranking by Excel count is very noisy.
  • Noise is strict on real grain. About 3.5% of real photos get Fail for night scenes or film grain. Accepted.
  • The misspelling clause costs some photos. About 0.3%, signs misspelled in reality. Accepted.
  • Feature Matching is unstable. Its Fails overlap little between prompt versions; not suitable as a hard filter on its own.
  • Truncation. 1.3% on real photos, 14% on text-heavy images. The truncated dimension is null.
  • Anatomical Fidelity bias. It rewards visible pores and fine lines, which may penalize retouched or studio portraits.
  • No criterion for collages or watermarks. Once the existing filter is replaced, nothing in Q-Judger stops these two.
  • Calibrated on one table only. All 1,000 images come from the Aesthetic-Train-V2 slice; images from other sources are unverified.
  • The orientation flag misses some. It catches about two thirds of images rotated 90 degrees and misses some clearly rotated ones; it raised no false alarm on upright photos in the test. Only 50 images were tested.

9. Open questions

  • The filter rule: where to put the gate, and how to rank the top 2.5%.
  • Whether to build a probability-based expected score for ranking.
  • Watermarks: keep using the existing filter's watermark column, or ignore them.
  • NSFW: keep using the existing filter's nsfw column, or add a call for Safety & Compliance.
  • What to do about collages.
