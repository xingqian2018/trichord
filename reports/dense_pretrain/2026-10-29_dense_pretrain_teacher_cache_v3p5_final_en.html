3p5 final data plan: dense pretrain teacher cache format (top-64)

top-64 + next-token rank + off-top-64 samples · 2026-10-29 · Status: format final, code written (CPU tests pass, not yet run on GPU)

This format applies to any teacher used for dense pretraining. The target corpus is about 15T tokens of pretraining data.

Changes from v2.1 (2026-10-17_dense_pretrain_teacher_cache_v2): (1) only the top-64 is stored (v2.1 stored the top-128); (2) only one tail sample set, off64, is kept; off128 is dropped; (3) the off64 total tail mass and the three tail statistics are stored directly (v2.1 derived them from the off128 values by adding back ranks 65–128). Units, uint24, next-token rank and logp, the vocabulary restriction and per-row random numbers are unchanged. Row size 694 → 354 bytes.

1. Overview

  • top-K main data: ids (uint24) and log probabilities (float16) of the sorted top-64; the id of the actual next token together with its rank (next_token_id_and_rank), and its log probability (next_token_logp, stored for every row).
  • off-top-K data: the total tail mass outside the top-64 and three tail statistics; plus one tail sample set, off64: 4 samples drawn with replacement from the renormalised distribution outside the top-64, storing ids and log probabilities.
  • Why tail samples: training uses exact_k = 64; the top-64 is computed exactly and the tail is estimated without bias from these 4 samples.
  • Why tail statistics: they give the teacher's exact entropy, ‖p‖², and the tail mass at temperatures T = 0.5 and T = 2. These are sums over the full vocabulary, so they can only be computed while the teacher scores; afterwards they could only be roughly estimated from the 4 samples.
  • 354 bytes per row; about 5.3 PB in total for 15T tokens of pretraining data.

2. Units and directory layout

Units follow the existing mechanism: one directory per prefix; large prefixes are cut at document boundaries into parts/<lo>-<hi>/ by the producer's plan_units (current implementation in dpl/distill/producers/vllm_topk.py).

Shared storage directory: /scratch/fsw/portfolios/cosmos/projects/cosmos_base_training/cosmos3_llm_datasets/pretrain/tc/<model>/, where <model> is the teacher name (e.g. mimo-v2.6-pro-rl).

/scratch/fsw/portfolios/cosmos/projects/cosmos_base_training/cosmos3_llm_datasets/pretrain/tc/<model>/<blend_hash>/<prefix_key>/      # main directory or parts/<lo>-<hi>/
    meta.json
    docs.idx
    top64_id.bin              top64_logp.bin
    next_token_id_and_rank.bin    next_token_logp.bin
    off64_tail_logp.bin           off64_tail_stats.bin
    off64_sample_id.bin       off64_sample_logp.bin
  • Unit: the main directory or one parts/<lo>-<hi>/ directory. Each unit is a complete, self-contained cache with its own meta.json and docs.idx; row_start is a row number local to the unit.
  • Cut points: strictly at document boundaries. A document never spans two units, so recomputing one unit never affects its neighbours.
  • Unit size: set by --part-tokens.
  • Reading: readers can open the units directly; parts never need to be merged.
  • Concurrency: one writer per directory (writer.lock); jobs are split by unit across a Slurm array.

3. File definitions

Let n be the total number of rows over all cached documents in the unit. Every .bin is a headerless, little-endian, row-major fixed-size array and can be read with np.memmap.

File Shape dtype Content
top64_id.bin [n,64,3] uint8 ids of the 64 tokens the teacher considers most likely as the next token (uint24, little-endian), in descending order of probability
top64_logp.bin [n,64] float16 their log probabilities (natural log, T=1), descending
next_token_id_and_rank.bin [n] uint32 id<<8 | rank: id is the actual next token (uint24); rank is its position 0..63 in the top-64, or 255 if it is not in the top-64
next_token_logp.bin [n] float16 teacher log probability of the actual next token (T=1), stored for every row; equals top64_logp[rank] when rank < 64
off64_tail_logp.bin [n] float16 log Σ_{i∉top-64} p_i: logsumexp over the log probabilities outside the top-64, computed in float32, then cast to float16. Do not use log(1 − Σ top-64 probabilities): the subtraction loses precision when the tail is small
off64_tail_stats.bin [n,3] float16 logs of three sums over the tokens outside the top-64: [:,0] = log(−Σ p log p), [:,1] = log Σ p², [:,2] = log Σ √p (definition and use below)
off64_sample_id.bin [n,4,3] uint8 4 token ids (uint24) sampled with replacement from the (renormalised) tail distribution outside the top-64
off64_sample_logp.bin [n,4] float16 teacher log probabilities of these 4 tokens (T=1, not conditional probabilities)
docs.idx [documents,3] int64 one (doc_idx, row_start, n_rows) per row, sorted by doc_idx
meta.json — JSON format version (dpl.teacher_cache/2.2), teacher, k=64, m=4 for the sample set, temperature, random-number rule, definitions of the three tail statistics, vocab_limit, blend_hash, row count, and the byte size and checksum of every file

Row semantics: a document of L tokens (including its final EOD) has L−1 rows. Row t is the teacher's prediction of token t+1 after seeing the first t+1 tokens; its row number in every file is row_start + t.

Vocabulary restriction: the teacher distribution is computed over Qwen3's 151,669 tokens only (ids 0–151668). Logits with id ≥ 151669 (MiMo-V2's 6 extra special tokens 151669–151674, and the output-layer padding rows up to 152575) are set to −∞ before normalisation: lp_i = z_i − log Σ_{j<151669} exp(z_j). Every id in every file is therefore < 151669 and compatible with the Qwen3 vocabulary; meta.json records vocab_limit = 151669.

Teacher vocabularies checked (2026-10-29, read directly from tokenizer.json and config.json): the 3p5 teacher is MiMo-2.5-Pro-Base or MiMo-2.6-Pro-RL; both are restricted to the 151,669 ids by the rule above.

Model Real ids First 151,669 ids identical to Qwen3 Tokens with id ≥ 151669 Output dim (incl. padding) EOD
Qwen3-32B 0–151668 — none 151,936 151643
MiMo-2.6-Pro-RL 0–151674 yes 6 audio/video special tokens (151669–151674) 152,576 151643
MiMo-2.5-Pro-Base 0–151668 yes none 152,576 151643

With the limit at 151669, MiMo-2.6 loses its 6 special tokens and the padding rows (151675–152575), MiMo-2.5 only the padding rows (151669–152575). EOD (<|endoftext|>) is 151643 in all three.

Reading and writing uint24: ids are below 2^24 (the teacher vocabulary must be ≤ 16,777,216; all current teachers qualify). Each id takes the 3 uint8 bytes a[..., 0..2] of the last dimension, little-endian (low byte first):

byte:   a[...,0]          a[...,1]              a[...,2]
        bit 7..0          bit 15..8             bit 23..16
write:  id & 0xFF         (id >> 8) & 0xFF      (id >> 16) & 0xFF
read:   id = a[...,0] | (a[...,1] << 8) | (a[...,2] << 16)      # cast to int32 before shifting
  • That is, a[...,k] = (id >> 8k) & 0xFF (k = 0, 1, 2), i.e. id = a[0] + a[1]·2^8 + a[2]·2^16 (a[0] is the lowest byte).
  • Example: id = 1000 = 0x0003E8 → [0xE8, 0x03, 0x00] = [232, 3, 0]; decoding gives 232 + 3×256 + 0×65536 = 1000.

Reading and writing next_token_id_and_rank: one uint32 whose high 24 bits are the id and low 8 bits the rank.

bit:   31 ............... 8 | 7 ...... 0
       id (24 bits)         | rank (8 bits)
  • Pack: v = (id << 8) | rank
  • Unpack: id = v >> 8, rank = v & 0xFF (the low 8 bits)
  • Example: id = 1000, rank = 3 → v = 1000×256 + 3 = 256003. Stored little-endian, byte 0 is the rank and bytes 1–3 are the id.

Computing off64_tail_logp: p_i is the teacher probability of token i (T = 1), lp_i = log p_i.

off64_tail_logp = log Σ_{i∉top-64} p_i = logsumexp_{i∉top-64} lp_i

That is, the log of the summed probability of every token outside the top-64. Sum the tail directly with logsumexp rather than computing log(1 − Σ_{top-64} p_i): the subtraction loses precision when the tail is small.

Definition of off64_tail_stats: every sum runs over the tokens outside the top-64; p is the full T=1 distribution.

[:,0] = log( −Σ p_i log p_i )    the tail's contribution to the teacher entropy
[:,1] = log( Σ p_i² )            the tail's contribution to ‖p‖², also Σ p_i^(1/T) at T = 0.5
[:,2] = log( Σ √p_i )            Σ p_i^(1/T) at T = 2
  • Use: teacher entropy H = −Σ_{top-64} p log p + exp([:,0]), for entropy weighting or skipping low-entropy positions. ‖p‖² = Σ_{top-64} p² + exp([:,1]); the ‖·‖² of the tail shape p/P_tail64 is exp([:,1]) / P_tail64², which sets the variance of tail sampling, i.e. how many samples are enough. At temperature T the teacher distribution is ∝ p^(1/T), with normaliser Σ_{top-64} p^(1/T) + Σ_{tail} p^(1/T): the second term is exp([:,1]) at T = 0.5 and exp([:,2]) at T = 2. For T between 0.8 and 1.33 the second term can be estimated from the 4 samples (P_tail64 · the sample mean of p^(1/T−1)).
  • Computation: as for the total tail mass, logsumexp in float32 over the log probabilities lp outside the top-64: [:,0] = logsumexp(lp + log(−lp)), [:,1] = logsumexp(2·lp), [:,2] = logsumexp(lp / 2). Drop tokens with p = 0 (lp = −inf) first, otherwise [:,0] becomes NaN. Rows with zero tail mass have −inf in all three columns.

No token_ids.bin: the id in next_token_id_and_rank is token t+1 of the corpus, so each row can be checked against the corpus directly; no separate input-token file is needed.

4. Next-token logp and consistency checks

The next token's log probability is stored for every row (next_token_logp.bin, dense float16), whether or not the token is in the top-64. Like every other .bin, the dense array is row-aligned, so there is no risk of misalignment from implicitly matching entries to the order in which rank==255 rows occur, and it can be np.memmap-ed instead of loaded whole.

  • Size: 2 bytes per row, about 30 TB for 15T rows, about 0.6% of the total.
  • Checks on read: for rows with rank < 64, next_token_logp must equal top64_logp[rank] (both come from the same float32 value, so they must be bit-identical after the float16 cast); for rows with rank == 255, next_token_logp must be ≤ top64_logp[63] and ≤ off64_tail_logp. Any mismatch is an error.
  • Commit order: as before, "write the data files first, then write docs.idx and meta.json atomically"; every .bin is written before docs.idx is committed (tmp + os.replace).
  • Blast radius of corruption: meta.json records a checksum for every file, so corruption only requires recomputing one unit.
  • Windows and context (added 2026-10-30): a document body longer than --window (default 8191) tokens is scored in windows: the first window is body[0:window]; every later window re-sends --window-context (default 2048) tokens before its first new row and keeps only the non-overlapping rows; the last window carries the EOD. Rows at positions ≥ window are therefore conditioned on context..window−1 preceding tokens, not on the full document prefix. Both parameters are recorded in meta.json (window, window_context, layouts.window) and in the plan file; the producer refuses settings that differ from the plan. Both values must be chosen explicitly before the 15T run (candidate: 32767 / 8192 with --max-model-len 32768, giving every row at least 8K of context; MiMo's native pre-training length is 32K).
  • Empty documents (added 2026-10-30): a document that is only an EOD, or empty, has 0 rows (no token predicts its first token) and is still written to docs.idx with n_rows = 0, so the unit can complete; readers must accept n_rows = 0 entries.
  • Tolerance of the statistic bounds (added 2026-10-30): when --validate checks log Σp² ≤ 2·log P, log Σ√p ≥ ½·log P and log(−Σp log p) ≥ log P + log(−log P), the tolerance is scaled per row by the ulp of each stored float16 value (for |x| ≥ 16 the fp16 spacing already exceeds a fixed 0.01); otherwise real data is flagged.
  • Packed mode (added 2026-10-31): the production corpus will be pre-packed into 8K / 32K training sequences; with --packed every corpus "document" is one pack and is scored whole, exactly as stored (no EOD appended, nothing trimmed, no windows; plain causal attention across the documents inside a pack, i.e. what a student trained without document masking sees). A pack of L tokens gives L−1 rows, row j = the prediction of token j+1; every pack must fit --max-model-len (an over-long pack is an error, never truncated). meta.json and the plan record packed, units of the two modes never mix, and --validate checks next-token ids by the pack rule. If the student trains with document masking, keep the document mode instead (scoring each document alone is the teacher-side equivalent of the mask).

5. Sampling rules

Let p be the teacher's full distribution at row t.

  • off64: q64(i) = p_i / P_tail64 (i not in the top-64); 4 samples with replacement.
  • Sampling must be done on the GPU from the teacher's full distribution, not from an approximation of the distribution outside the top-64.
  • Sampled tokens may coincide with the next token and with each other; this is expected with sampling with replacement.
  • Reproducibility: random numbers are deterministic per row. Each document has one key, 63 bits taken from sha256(blend_hash | prefix_key | doc_idx | seed); the uniform for sample j of row t is generated from hash(key, t, j) (53 bits), followed by inverse-transform sampling on the tail's cumulative distribution. Batching, window splitting, resuming after an interruption or recomputing a single document all draw the same samples. The rule is written to meta.json.
  • Precision: log probabilities, total tail mass and the three tail statistics are computed with logsumexp in float32 and cast to float16 only at the end; the tail cumulative distribution used for inverse-transform sampling is computed in float64, so tokens with very small probability can still be drawn.
  • Fused tail pass and chunk dependence (added 2026-10-31): the plugin computes the tail statistics and the samples in one pass: one fp32 exp (per-row max subtracted), plain sum reductions, and a two-level float64 inverse CDF (block masses, then inside the selected block). Against a per-row numpy float64 reference the trailer differs by ≤ 2e−6 absolute and all 3072 test samples agree; 9.0 ms → 3.9 ms per 512 rows on GB300. Known non-determinism: fp32 CUDA reductions (the logsumexp of restrict_vocab_, and vLLM's own log_softmax) sum in an order that depends on the number of rows in the chunk, so the last bit can differ: with a different chunking about 0.005% of the top-64 log-probabilities differ by one float16 ulp and 0.01–0.05% of the samples move to a neighbouring id; identical shapes reproduce bit for bit. This is far below the MoE teacher's own run-to-run jitter (mean KL 0.006 nat) and is left as is.
  • Feasibility: the producer (tools/distill/dense_teacher_cache_producer_3p5.py in the Dense-Pretraining-LMs repo) and plugin (tools/distill/vllm_offtopk_plugin_3p5/) of this format are single-sample-set copies of the v2.1 code, which is left unchanged; v2.1 is already in production with the same vLLM hooks on MiMo-2.6's 45B and 650B corpora. Other teachers need to be re-validated on their own models.
