# ArchScale 如何拟合 LR 与深度、训练量的关系，以及我们在 Qwen3 ladder 上的重拟合（TODO 3）

> 公式本身、MuonH / HyperP 的来龙去脉见 [HyperP.md](HyperP.md)，优化器细节见 [Muon.md](Muon.md)。本文只讲**这个 LR 公式里的系数是怎么测出来的**，以及我们怎么在自己的模型上重测。

## 0. 一句话

MuonH 的学习率由一个公式给出。**ArchScale 用"固定其他条件、只改一个变量、在每个点上扫 LR 找最优"的办法，分别测出了这个公式里的 token 指数和深度规则。** 我们的 TODO 3 用同样的办法，在 Qwen3-MoE ladder 上把这几个系数重测一遍。

---

## 1. 要拟合的公式

```
η = η0 × sqrt(8 / L) × (T / 10.4B) ^ -0.32
     ①        ②               ③
```

| 部分 | 含义 | 原文出处 |
|---|---|---|
| ① η0 = 0.016 | 起点：d = 8 层、10.4B token 时的最优 LR | §4.1、Table 4（拟合值 0.01515） |
| ② sqrt(8/L) | 深度规则（Depth-μP）：层数越多 LR 越小 | 理论 §3.3（Theorem 3），实验 §4.2 / Table 7 |
| ③ T^-0.32 | token 规则：训练越长 LR 越小 | 纯经验 §3.4 / Table 4（Eq. 8：η* = 24.27·T^-0.320） |

宽度不出现在公式里：球面约束把宽度的影响吸收掉了（见 HyperP.md §1）。batch 项在我们这里为 1（GBS 固定 2M token）。

## 2. ArchScale 原文是怎么拟合的

### 2.1 基本方法：一个点上怎么找"最优 LR"

1. 固定模型和训练量，在一组 LR 上各训一个模型（原文用 8–10 个点的细网格）。
2. 在 **log(η)** 上对这些 loss 拟合一条**抛物线**，最低点就是最优 LR η*（不必恰好落在网格点上）。
3. 敏感性分析（Figure 11 / Table 14）：**5 个点就够**。最坏情况下最优 LR 误差约 4.1%，但对应的 loss 误差只有约 0.04%（约 0.001 nats），因为 loss 对 LR 是二阶不敏感的。

### 2.2 token 指数 ③：固定深度，只改训练量

固定 d = 8（208M 参数），训练 token 从 10.4B 翻倍到 166.4B，每个预算各扫一遍 LR（Table 4）：

| 训练 token | TPP | 最优 η* | 最低 loss |
|---:|---:|---:|---:|
| 10.4B | 50 | 0.01515 | 2.4741 |
| 20.8B | 100 | 0.01208 | 2.4189 |
| 41.6B | 200 | 0.00958 | 2.3773 |
| 83.2B | 400 | 0.00772 | 2.3456 |
| 166.4B | 800 | 0.00635 | 2.3214 |

在 log-log 坐标上是一条直线：**η* = 24.27 · T^-0.320**，留一法交叉验证的平均误差 1.5%。指数 0.32 与 Bjorck 等人在 AdamW 上找到的值一样（原文称为"magic exponent"）。

### 2.3 深度规则 ②：固定训练量，只改深度

宽度和深度一起放大（w = 128·d，保持形状），**训练 token 固定为 10.4B**，在 5 个深度上扫 LR，分别比较"用 Depth-μP"和"不用"（Table 7；TPP 是我按参数量算的）：

| 深度 d | 参数 | TPP（10.4B） | 用 Depth-μP 的 η* | 不用 Depth-μP 的 η* |
|---:|---:|---:|---:|---:|
| 8 | 208M | 50 | 0.014 | 0.016 |
| 12 | 570M | 18 | 0.016 | 0.012 |
| 16 | 1.24B | 8.4 | 0.016 | 0.010 |
| 20 | 2.31B | 4.5 | 0.016 | 0.008 |
| 24 | 3.90B | **2.7** | 0.014 | 0.008 |

- 不用 Depth-μP 时，最优 LR 从 0.016 掉到 0.008；用了以后（LR 再乘 sqrt(8/d)，残差乘 1/sqrt(2d)），基础 LR 稳定在 0.014–0.016，说明 sqrt(8/L) 这个深度规则有效。两种情况能达到的最低 loss 差不多。
- 深度越大，loss 对 LR 越敏感（d = 20 时 LR 偏大一档就多 0.098 nats），所以深模型上 LR 偏了代价更大。
- **注意 1**：原文同一段既说"所有深度实验都在 10.4B token"，又说"at 50 TPP"。按 Table 7 的标题和参数量，实际是**固定 10.4B**，只有 d = 8 恰好是 50 TPP。
- **注意 2**：所以原作者的深度规则本身是在**越深越欠训练**的条件下测出来的（d = 24 只有 TPP 2.7），没有在充分训练（如 TPP 200）下验证过。

### 2.4 原文的其他设置（和我们不同的地方）

8 层起的 dense 模型、宽度 = 128 × 深度、SlimPajama、4K 上下文、2M batch、线性衰减到峰值的 **10%**、不做 warmup。batch 指数实测 0.558（Table 8），代码里用 sqrt。

## 3. 我们的重拟合：ladder 的 TODO 3

### 3.1 为什么要重测

我们和原文几乎每个条件都不一样：128 expert、top-8 的 MoE；宽度约 43 × 深度；QK-norm、GQA 4、152k 词表、8192 上下文；corpus v2；TPP 200；线性衰减到 **1%**；最深 48 层（原文只测到 24）。另外：

- MuonH 相对 AdamW 的优势随 rung 增大而缩小（overall_tw：q0–q3 依次 0.079 / 0.039 / 0.026 / 0.019），怀疑 LR 公式在大模型上偏了。
- 公式接下来要用在 q6（48 层、546B token）和 235B（TPP 约 1600）上。② 或 ③ 的指数差 0.1，LR 就差 20–30%。

### 3.2 方法：格子 + 网格搜索

- **格子** = 一个固定的（模型大小 L，训练 token T）组合。
- 每个格子：用公式算出 1×，再按 **0.7× / 1× / 1.2× / 1.4× / 2×** 各训一个模型；用 doc-isolated val_v2 打分；在 log(倍数) 上拟合抛物线，得到这个格子的**最优倍数 m\***（m\* = 1.2 表示公式算低了 20%）。
- 拟合结果：如果最低点落在边上，或 R² < 0.99，就再往外加一个点（0.5× 或 2.8×）。

每格 5 个倍数；"1×" 一列已有的标 **主线**，表示直接复用 ladder 主线的 MuonH run，不用重训。

| 2 | q0 | 12 | 28.8B | 600 | token 轴 ③ | `MUONH_LR*_TPP600` | 5 |

| 5 | q2 | 24 | 9.6B | 27 | 深度轴 ②（第一档） | `MUONH_LR*_IT4577` | 5 |

怎么读这张表：

- **看同一个 T（9.6B 一列：格子 1/4/5/6；30.8B 一列：格子 2*/7/8/9）**：模型变深，最优倍数怎么变 → 修 **②**。（*q0 的 28.8B 与 30.8B 近似同档。）
- **看 q0 一行（格子 1/2/3）**：模型不变，token 变多，最优倍数怎么变 → 修 **③**。
- 所有格子的整体偏移 → 修 **①**。

### 3.4 拟合与后续

1. 用 10 个格子的 m\* 做加权最小二乘拟合一个平面：
   ```
   log m* = a + b · log(L/8) + c · log(T/10.4B)
   ```
   得到新的 η0' = 0.016·e^a、深度指数 −0.5 + b、token 指数 −0.32 + c，以及各自的标准误差和每个格子的残差。
2. **可分离性检查**：同时单独拟合"只看深度"（9.6B 那一列）和"只看 token"（q0 那一行）。如果两者在误差范围外不一致，说明这个公式的形式在我们的范围内不成立，**照实报告，不硬选**。
3. 如果采用新公式（拟合之后的另外 9 个 run）：q3 上用新公式训一个验证 run（1 个），与主线 MuonH q3 配对；新公式在 q0 / q1 上补 seed 2、3（4 个）；BASE 和 Muon 在 q2 上补 0.5× / 2× 的 LR 检查，保证对比公平（4 个）。

**规模**：格子 47 个新 run + 拟合后 9 个 ≈ **56 个训练 run，约 16.5k GPU 小时**。

## 4. 讨论：这套设计能回答什么、不能回答什么

**能回答**：公式里 ①②③ 三个系数在我们的模型上是否需要修正，修多少；深度和 token 的影响能否分开处理。

**要小心的地方**

- **固定 token 的格子同时意味着"越深越欠训练"**（格子 4–6 的 TPP 只有 62 / 27 / 14）。训练越短，最优 LR 通常越大，所以这些格子里"越深越适合大 LR"混着欠训练的影响，不能单独归因于深度。原作者的深度规则也是这样测的（d = 24 时 TPP 只有 2.7），这是这种方法本身的局限。
- **两条轴覆盖的 TPP 区间不重叠**：深度轴在 TPP 14–87，token 轴在 TPP 200–1800。能不能拼起来，全靠第 3.4 节的可分离性检查。
- 对 ladder 最直接的证据是 **TPP 200 的主线格子**（1 / 7 / 10）：它们直接回答"在我们实际的训练配比下，最优 LR 随模型变大是否偏离 1×"。

**不能回答**：LR 调对以后，MuonH 在长训练上是否仍然和 AdamW 差不多。所有格子里都没有 AdamW。要回答这个问题，需要在长训练的格子（如 q0 的 TPP 600 / 1800）里也跑 AdamW（以及 Muon）做对照，这一组不在 TODO 3 里（每个约 200 GPU 小时，共约 600）。
