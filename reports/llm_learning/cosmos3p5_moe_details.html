TL;DR

  • 两层"MoE"含义不同。MoT 的 und / gen 是按模态硬切分的两座塔，_moe_gen 后缀指 generation 塔，不是路由 MoE。每座塔内部的 FFN 才是真正的路由 MoE。
  • und 塔完全冻结。它是 Cosmos3.5 Reasoner（Qwen3-VL-MoE 结构）原样的 softmax top-8 MoE，没有 LBL。
  • gen 塔是被训练的 MoE。从 und 塔整体拷贝初始化，然后改成 sigmoid router，加一个 shared expert，用 bias 控制器加 sample-level LBL 双重负载均衡。
  • 没有 Expert Parallel。专家张量只靠 FSDP 沿专家维切分，235B 上每卡正好 1 个专家。
  • 优化器是 Dion2WithAuxAdamW。专家权重按单个专家切片做正交化，router 权重走 AdamW。

gen 塔 MoE（被训练的部分）

每层的 mlp_moe_gen 是一个独立的 Qwen3VLMoeTextSparseMoeBlock。初始化时 init_moe() 把 und 塔的全部权重拷过来，包括 router 的 gate.weight。不拷的只有 und 塔本来就没有的东西：gate_noise、log_temperature、router_bias 和 shared_expert。

值得留意：gen 的 gate 权重是从按 softmax 训练的 Qwen router 拷来的，现在用 sigmoid 解释同一组 logits。softmax 只关心 logits 之间的差，sigmoid 还关心绝对值，所以训练初期 gen 的路由分布和 und 的不完全一致。这是读代码得出的推论，没有做实验验证。

Shared expert 的零初始化。shared expert 是 gate_up_proj [H, 2I] 加 down_proj [I, H] 的 SwiGLU。down_proj 初始化为零，所以训练开始时它的输出恒为零，不会扰动从 Reasoner 拷来的初始行为。宽度倍数 shared_expert_intermediate_scale 用默认值 1。

一次前向的路由流程

x: [T, H]                       # 打包后的 gen token，padding 已标记
logits = gate(x)                # fp32
s      = sigmoid(logits)        # [T, 128]，未加 bias 的分数
idx    = topk(s + expert_bias, k=8)          # bias 只影响"选谁"
w      = gather(s, idx)                      # 组合权重用未加 bias 的分数
w      = w / w.sum(-1, keepdim=True)         # 归一化到和为 1

routed = Σ_k  w_k · Expert_{idx_k}(x)        # grouped_mm 计算
out    = routed + SharedExpert(x)

# padding token：输入置零，组合权重为 0，路由到哨兵组，不计入统计
# LBL 统计：用"不加 bias 的自然 top-k"计数，概率 = s / s.sum(-1)

这里有两个关键的分离：

  • 选择和加权分开。expert_bias 只改变 top-8 选哪几个专家，组合权重仍然来自原始 sigmoid 分数。这是 DeepSeek-V3 的做法，bias 不会直接改变输出的数值尺度。
  • LBL 看的是自然分配。如果 LBL 用加了 bias 之后的计数，bias 已经把分配拉平，LBL 就看不到 router 本身的偏向，梯度会接近零。

负载均衡：两套机制同时开

① Aux-loss-free bias 控制器（不走梯度）

每个专家维护一个 buffer expert_bias。每个 optimizer step 前，on_before_optimizer_step 调用 moe_utils.update_expert_biases，只作用于 gen 塔的 MoE block：

counts = all_reduce_DP(tokens_per_expert)       # 本步各专家分到的 token 数
avg    = counts.mean()
bias  += update_speed * sign(avg - counts)      # 偏少的专家 bias 上调，偏多的下调
bias  -= bias.mean()                            # 去均值
bias   = clamp(bias, -max_bias, +max_bias)
tokens_per_expert.zero_()
参数Cosmos3.5 设定类默认值
update_speed0.00020.001
max_bias0.050.5

两个参数都比默认值温和很多。sigmoid 分数在 0 到 1 之间，±0.05 的上限意味着 bias 只能在分数接近的专家之间调换选择，不能强行把明显不相关的专家拉进来。这个 buffer 也会同步到 net_ema。

② Switch 风格 LBL（带梯度）

L_lbl = E · Σ_i  f_i · P_i
  f_i : 专家 i 在自然 top-k 下分到的 token 比例
  P_i : 专家 i 的平均路由概率（sigmoid 分数在 128 个专家上归一化）
  E   : 专家数 128
  • method="sample" 表示按 packed sequence 里的每个原始样本分别计算 f 和 P，而不是整个 batch 一起算。
  • 统计量先在 CP 维度上求和，再在层之间取平均。
  • padding token 放进哨兵桶，不参与统计。
  • 最后以 aux_loss_gen 的形式乘 0.04 加到总 loss 上。
分工：bias 控制器负责每一步的实际分配是均衡的，起效快但不改 router 权重。LBL 负责通过梯度把 router 权重本身往均衡方向推，起效慢但是从根上解决。

专家计算与并行

Grouped GEMM

  • 每层专家权重融合成两个 3D 张量：gate_up_proj [128, H, 2I] 和 down_proj [128, I, H]。
  • token 按专家排序，每组长度对齐到 16，排列索引由一个 Triton kernel 生成。
  • 两次 torch._grouped_mm 完成所有专家的 up 和 down 投影，最后 scatter_add_ 按组合权重还原到原顺序。
  • padding token 被路由到一个哨兵组，不参与计算。

一句话总结：Cosmos3.5 generator 的 MoE = 冻结的 Reasoner MoE（und）+ 从它拷出来、改用 sigmoid router、加 shared expert、用 bias 控制器和 sample-level LBL 双重均衡的 gen MoE；训练只走 FSDP，不做 EP。相关背景见同目录的 moe_router.md 和 Muon.md。
