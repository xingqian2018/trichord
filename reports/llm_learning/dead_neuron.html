0. 速览

  1. 判据：一个 SwiGLU 神经元的 gate 行、up 行、down 列的范数同时低于各自矩阵中位数的 5 %，算死。只看权重，不跑数据。核对
  2. 直观结果：死神经元对任何输入的输出都约为 0，等于被删掉。这一层按死亡比例变窄，参数和计算照样占着。推导
  3. 不是激活饱和：不是 gate 卡在负半轴，而是权重被优化器一步步缩没了。这批神经元在第 2,000 步时 gate 的 sigmoid 均值是 0.48。会话
  4. 成因是 hyperball 的 "税"：每步把整个矩阵缩回固定范数时，没在动的行被扣掉 κ × LR² 的范数（κ ≈ 15）。SwiGLU 是三个因子相乘，一个神经元一旦落后，三个因子的更新同时变小，交不起税，一路缩到零。会话
  5. 矩阵形状决定谁会落后：正交化在 "高" 矩阵（行数多于列数）上不够分，弱的行拿不到足额更新。第 0 层 dense 最高，死得最多；shared expert 是宽矩阵，一个不死。会话
  6. 对 LR 是悬崖：税按 LR² 涨，信号按 LR 涨。q2 上 0.7× LR 路由层不死，1.4× 路由第 1 层死 36 %。会话
  7. 只出现在 SwiGLU MLP：第 0 层 dense 和前几层路由 expert。attention、router、latent projection、shared expert 都是 0。会话
  8. 死了不会复活：59B 第 24,000 步已死的 4,254 个，到第 34,000 步复活 0 个。会话
  9. 对 loss 几乎没有影响：把死亡完全消掉，loss 相差不到 0.002；59B 第 0 层 23 % 的死亡至多值约 0.001 nats；2× LR 下前三层路由死掉一半以上，loss 曲线仍与零死亡的对照重合（早期读数）。会话
  10. 修法：按行约束把死亡完全消掉；拆球面（Muse 的做法）消掉约九成的路由死亡；router LR 和 SiTU-GLU 无效。会话
  11. 当前决定（11-14）：不修，只监控。461B 的结构和优化器不动，靠把 LR 定在悬崖以下。会话
  12. 判据的盲区：一个 expert 死掉一半以上时，中位数本身是死的，判据会把死亡比例报得偏低。会话

1. "死" 的几种说法

说法 判据 需要跑数据吗
ReLU 死神经元 激活前值对所有输入都为负，输出和梯度恒为 0 需要
休眠神经元（GELU / SiLU） 激活频率接近 0，或平均绝对激活远低于同层平均 需要
权重判据（本笔记用的） 这个神经元的输入权重和输出权重的范数都接近 0 不需要

"死" 也会用在别的单元上：从不被选中的 MoE expert、输出接近 0 的注意力头、从未更新的 embedding 行、从不激活的 SAE 特征。本笔记只讲 SwiGLU MLP 的隐藏神经元。

2. 本项目的判据核对

代码在 share/cosmos_llm_scaling_ladder_wt_prod/prod_xx/param_health/，三个脚本用同一条规则：ph_scan.py（L235–259）、ph_report.py（L42–45）、muse_dead_scan.py（L31–33）。整理后是：

def dead(ss, axis=-1):                 # ss：每一行（或每一列）的平方和
    n = np.sqrt(ss)
    med = np.median(n, axis=axis, keepdims=True)
    return n < 0.05 * med              # 低于同一矩阵中位数的 5 %

g, u = dead(rss[..., :H]), dead(rss[..., H:])   # fc1 的前 H 行是 gate，后 H 行是 up
c = dead(css_fc2)                               # fc2 的每一列
neuron_dead = g & u & c                         # 三者同时低，才算死
  • 比较对象：同一个矩阵自己的中位数。每个 expert 单独算；gate 半、up 半、fc2 三块分别算。
  • 为什么要求三者同时低：见 §4.3。
  • 盲区会话：一个 expert 死掉一半以上时，中位数本身就是死的，规则失效。q2 的 2× LR run 因此被低估（§6.2）。会话改用了一条不受此影响的规则重算，具体规则我没有看到。
  • 成本会话：一个 59B checkpoint 在 CPU 上约 3 分钟。

3. 一个 SwiGLU 神经元在做什么推导

设输入是 x（C 维，过了 norm 的残差流），隐藏宽度是 H。第 j 个神经元有三段权重，都是 C 维：

  • gate 行：fc1 的第 j 行。
  • up 行：fc1 的第 H + j 行。
  • down 列：fc2 的第 j 列。
g_j    = gate行 · x                  # 标量：门的开度
u_j    = up行 · x                    # 标量：要传的信号
贡献_j = silu(g_j) × u_j × down列    # C 维向量
MLP(x) = Σ_j 贡献_j

每个神经元用两行权重从 x 里读出两个标量，相乘得到一个强度，再沿 down 列这个固定方向写回残差流。

4. 为什么 "死" 等于被删掉推导

4.1 三个因子各自被范数卡住

  • |u_j| ≤ ‖up行‖ × ‖x‖：up 行缩到 5 %，u_j 最多也只有原来的 5 %。
  • |g_j| ≤ ‖gate行‖ × ‖x‖：gate 行缩小后 g_j 接近 0，而 g 很小时 silu(g) ≈ g / 2，门的输出也跟着缩到接近 0。
  • ‖贡献_j‖ 正比于 ‖down列‖。

x 过了 norm，范数基本固定，所以这些上限对任何输入都成立：没有哪个输入能把它唤醒。这是权重判据和激活统计判据的区别。

4.2 数量级

归一化单位下的粗算：

神经元 g silu(g) u ‖down列‖ 贡献大小
正常 1 0.73 1 1 0.73
刚好压线的死神经元（各 5 %） 0.05 0.026 0.05 0.05 6.4e-05
  • 压线的死神经元的贡献约是正常神经元的万分之一。
  • 实际死掉的神经元远低于这条线会话：Kimi K3 里最小的只有中位数的 0.15 %。
  • 删掉神经元 j（去掉 fc1 的两行和 fc2 的一列），输出的变化正好等于 贡献_j。所以把死神经元全部删掉，模型输出几乎不变。

4.3 为什么判据要求三者同时小

  • 只看输出：三个因子里任何一个接近 0，贡献就已经接近 0。
  • 但只有一个小的神经元还能恢复。例如只有 down 列小，它的梯度正比于 silu(g_j) × u_j，这个值不小，down 列能长回来。
  • 三者都小时，每一段权重的梯度都要乘上另外两个接近 0 的因子，既没有输出也没有梯度。
  • 实测会话：三组几乎同时死。59B 第 0 层上 gate 行、up 行、down 列各死 1,600 / 1,597 / 1,600 个，只差 3 个。

4.4 "输出不变" 和 "容量价值" 是两回事

  • 删掉死神经元，当前模型的函数不变。
  • 这部分容量如果活着能带来多少收益，是另一个问题，要靠 ablation 来量（§7）。

5. 为什么会死会话

5.1 "税"：整矩阵缩回扣掉没在动的行

  • hyperball 每步更新后，把整个矩阵乘同一个系数，缩回固定的总范数。
  • 一个这一步没拿到更新的行，范数会被这个系数直接扣掉一部分。每步扣 κ × LR²。
  • κ 实测约 15（59B 上 15.1–15.9，q0–q3 上 13.7–16.8），理论值是 (1 + μ) / (2 (1 − μ)) = 19.5（Muon 动量 μ = 0.95）。
  • κ 大于 1/2 的原因是动量：连续多步的更新方向相同，矩阵整体向外长，缩回时再从所有行等比例扣回去。
  • 它在所有层、所有矩阵类型上都一样。正常在更新的行刚好把扣掉的赚回来。
  • CPU 测试：完全没有梯度的神经元在现在的规则下每步缩到 0.9965–0.9979 倍。按这个速度，约 850–1,400 步就缩到 5 % 以下推导。

5.2 三因子乘积：一旦落后就交不起税

  • 一个神经元的三个因子，每一个拿到的更新都正比于另外两个。
  • 一旦落后，三个因子的更新同时变小，赚回来的少于被扣的，一路缩到零。
  • gate 没有饱和关死：这批神经元在第 2,000 步时 gate 的 sigmoid 均值是 0.48。
  • 玩具实验里让弱行不参与缩放，病态的行自己长了回来。说明梯度一直都在，杀死它们的只是税。

5.3 为什么对 LR 是悬崖

  • 税按 LR 的平方增长，信号按 LR 线性增长。
  • 路由 expert 的死亡比例约按 LR 的 9 次方上升（82 个 run、205 个 checkpoint 的扫描）。

5.4 矩阵形状：哪些行会落后

  • 优化器每步把更新做正交化。高矩阵做正交化时，足额的独立方向只有列数那么多，行数更多就不够分。
  • 弱的行拿到的更新和它自己的动量成正比，越弱越少，然后被统一的缩回系数压小。
  • 宽矩阵里每一行都能拿到足额更新，弱的行会被推回来。
  • 多做几步正交化没用，换成精确正交化也没用，问题在形状。
矩阵 形状（行 × 列） 高 / 宽 实测

  • 谁会死很早就定了：只看前 5 % 的训练，就能以 0.93 的 AUC 预测。
  • 和初始范数无关：用初始范数预测，AUC 只有 0.51–0.53。不同 run 的死亡名单重合度是随机水平的 2 倍多，所以决定因素是神经元初始的方向。

税和形状的关系是我的整理推断：税解释了落后的行为什么会一路缩到零，形状解释了哪些行会落后。玩具实验里去掉正交化、只用普通动量，仍然有死亡（96 / 88 个），说明税本身不依赖正交化。

5.6 还没查清的

  • 第 0 层那批行最初为什么落后。它发生在第一个 checkpoint（第 2,000 步）之前，当时已有 925 个 gate 行低于中位数的一半。
  • 路由 expert 为什么越靠前的层死得越多。第 1 层的动量里可用的独立方向只有 321–355 个（满额 512），更深的层有 503–506 个；但这个读数取自已有三分之一神经元死亡之后，有循环论证的成分。
  • 玩具实验里高矩阵拆两半反而死得更多（17.8 % 对 6.9 %），GPU 上第 0 层是略有改善（29.9 % → 25.1 %），两者不一致。

各实验改了什么：

  • A、B：对死亡没有影响。SiTU-GLU 在 0 附近和 SwiGLU 相同，改的只是大激活值的上限。
  • C：路由 expert 单独降 LR，路由死亡消失，第 0 层反而更多。q0 上最终 R1 差 0.022。
  • D（--hyperp-mlp-rows）：更新方向和步长不变，只改 "拉回球面" 的方式。fc1 的每一行、fc2 的每一列各自缩回自己上一步的范数，不再被别的行抽税。
  • 代价：每个神经元的范数被固定在初始值，不能自己变大变小。没有任何参考模型这样做。
  • 必须从第 0 步开：中途打开救不回已死的神经元。
  • 实现限制：只支持没有被 TP 切分的参数，遇到切分的会报错。
  • E（--hyperp-split-gate-up-spheres）：gate 半和 up 半在优化器里当成两个独立矩阵，加上 fc2 是每个 expert 三个球面，即 Muse 的做法。每一半内部的行仍共用一个缩回系数。
  • 起保护作用的是 "正交化对多大的块做"。单独步长、单独缩回、gate 和 up 分开本身都没有作用（玩具实验）。
  • 第 0 层拆开后仍是高矩阵，所以救不了第 0 层。
  • F：按行约束只作用于第 0 层 dense。
  • G：模型不动，优化器把第 0 层 dense 切成 9 块（每块 384 个神经元），每块单独正交化、单独步长、单独球面。它不固定任何神经元的范数，是 F、G 里更温和的一种，同时验证了 §5.4 的形状解释。

9. 当前结论和还没出的结果会话

决定（11-14，用户提出 "这个 dead 是不是其实不用修"，会话收回了 "461B 从第 0 步打开按行约束" 的建议）：

  1. 461B 不加按行约束，第 0 层保持 dense，结构和优化器都不动。
  2. 防悬崖靠 LR：按 law 把 LR 定在悬崖以下。
  3. 训练中监控：每个 checkpoint 扫一次死亡比例。路由层如果快速上升，就是 LR 偏高的信号。
  4. 如果以后真要修，先考虑更温和的拆球面。
