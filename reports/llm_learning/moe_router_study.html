MoE router 学习笔记

router 怎么选 expert、怎么学、怎么保持负载均衡；三种 Quantile Balancing（QB / QBX / QBK3）的区别；健康指标怎么看。

先看这里

每一条后面都有详细的一节。

两个用途

router 的分数既决定选谁（取前 k 个，没有梯度），也决定权重（有梯度）。bias、β 这些"门槛"只影响选谁，不进权重。

权重

g = 2.5 × σ(z) ÷ 选中那 k 个的 σ 之和。只在选中的里归一化，加起来是 2.5，不是 1。

梯度

router 只能从权重 g 拿到梯度，而且只在选中的 expert 之间挪份量。冷门 expert 选不上，就拿不到梯度，所以需要不走梯度的均衡手段。

QB 的门槛

β 是每层每个 expert 一个，存进 checkpoint；α 是每个 token 一个，现算现扔。没有"整层一个"的门槛。

QB / QBX / QBK3

QB：logit 空间，每个 micro-batch 各取分位数再平均。QBX：logit 空间，全局合并。QBK3：sigmoid 空间（就是 DSV3 的 bias），全局合并，生产在用。

结果

loss 上四种做法（只用 bias、QB、QBX、QBK3）分不出高低。差别在健康指标：QB 后期 MaxVio 停在 1.4，QBK3 的 bias 始终很小（≤ 0.10），底座的 bias 涨到 7。

1router 一步在做什么

一个 token 进来，router 算出每个 expert 的分数，用它选出 k 个 expert，再用同一组分数给这 k 个 expert 定权重。

权重怎么算

scores = sigmoid(logits)                    # 全部 E 个 expert
# 选下标：DSV3 / QBK3 用 topk(scores + bias)；QB / QBX 用 topk(logits - beta)
scores = gather(scores, top_indices)        # 只取选中的 k 个，不含 bias
probs  = scores / scores.sum()              # 在选中的 k 个里归一化（k = 1 时不做）
probs  = probs * 2.5                        # --moe-router-topk-scaling-factor

例子：选中了 3 个 expert

expert 1expert 2expert 3
logit z2.00.0−1.0
σ(z)0.8810.5000.269
在选中的里归一化（和 = 1）0.5340.3030.163
× 2.5 = 实际权重1.3350.7580.408
对比：在选中的里做 softmax0.8440.1140.042

sigmoid 后归一化比 softmax 平得多：softmax 用指数放大差距，sigmoid 在两端饱和，差距被压扁。直接归一化 z 行不通，因为 z 有正有负，和可能是 0。

几个模型的写法：DeepSeek-V2 用 softmax，选出前 k 个后不重新归一化；DeepSeek-V3 就是上面这套，另有分组限制路由（我们没开）；Kimi K3 也是这套，但 896 个 expert 选 16 个、2 个 shared、不乘 2.5。

2router 怎么学

选谁这一步没有梯度，bias 和 β 也没有梯度。router 只能通过选中的那几个 expert 的权重学习。

对选中的 expert i

∂L/∂zi = gi · (1 − pi) · (ai − ā)

p = σ(z)；ae = ⟨∂L/∂y, Experte(x)⟩，越负说明这个 expert 越有用；ā 是选中的 k 个按权重求的平均。没选中的 expert：∂L/∂z = 0。

  1. 只在选中的 expert 之间挪份量。比平均更有用的 expert，logit 被推高；更没用的被压低。按权重加起来，这些梯度正好抵消，不会把它们整体推高或压低。
  2. 排名只能间接变化。一个 expert 进出前 k 名，要靠它被别的 token 选中时得到的更新，或者输入 x 本身变了。冷门 expert 选不上就拿不到梯度，会越来越冷，所以需要 bias、β 这类不走梯度的均衡手段。
  3. 饱和会切断梯度。gi(1 − pi) 和 σ'(z) 成正比：
zσ(z)σ'(z)z 加 1 时 σ 增加
00.50.250.23梯度畅通
20.880.100.07
40.9820.0180.012饱和阈值
60.99750.00250.002基本传不过去

例子：某个 token 选中了 A，梯度说"A 很有用，权重该再大一点"。zA = 0 时，把 zA 调大一点，权重明显上升；zA = 6 时，σ 已经是 0.9975，再怎么调也几乎不变，这个信号到这里就断了。

饱和只切断经过 σ 的那几条路：

路径（看一个被选中的 expert）经过 σ' 吗饱和时
① loss → 这个 expert 自己的参数不经过照常学习
② loss → g → s → z → Wr经过被切断：router 学不动
③ loss → g → s → z → 隐状态 x经过被切断，但这条本来就细

aux loss 的梯度也走 ②，饱和时同样变弱。所以在 DSV3 里，"logit 失控"和"均衡全靠 bias 撑"往往一起出现。

推导

记 we = pe / Σj∈S pj，ge = 2.5 we。∂ge/∂zi = (δei − we) · gi (1 − pi)。代入 ∂L/∂zi = Σe ae ∂ge/∂zi 就得到上式。Σi gi(ai − ā) = 2.5(Σ wiai − ā) = 0。

4aux loss

Laux = α · Σe fe · Pe
  • fe：这个 expert 被选中的比例，乘 E/k，完全均衡时为 1。它是数出来的，不可导。
  • Pe：所有 token 给它的平均分数，可导，梯度只经过它。fe 大的 expert，Pe 被往下压。
  • 每张卡只用自己的 token 算 Pe，所有卡的部分加起来才是完整的 loss。
  • aux loss 只更新 router 权重，不碰 expert bias。
  • seq aux 用来数 fe 的前 k 名不加 bias，和实际路由不是同一个；Pe 在全部 E 个 expert 上归一化，所以梯度会流到没选中的 expert 上。
配置每次统计多少 token
老 ladder aux_loss（8K）q0–q3：32,768；q4：16,384；q5、q6：8,192。随 rung 变小，11-05 手册筛查列为问题
老 ladder seq_aux每条 8,192
PROD1、E2X 的 seq_aux每条 32,768，正好等于一个 micro-batch

aux_loss 不跨卡，也不跨 micro-batch：一步 2M token 被切成 64 个互不相关的 32K 小块，各算各的。老 ladder 没用 global_aux_loss，是因为当时 fork 里它的系数实际是 1e-3 / DP，不同 rung 之间差 16 倍。

复杂一点的例子：64 张 GB300 训练 Qwen3-235B-A22B（切分方式是假设的）

TP 2（开 SP）、PP 4、CP 1，所以 DP = 8。每个 stage 16 张卡，EP 16。序列 8192，每次 2 条，GBS 1024 条，所以一个 DP 副本一步要跑 64 次。

  • aux_loss：fe 在 TP 两张卡之间汇总，覆盖 16,384 个 token；一步里有 512 个互不相关的小块。
  • seq_aux：每条序列 8,192 个 token，一步 1024 个 loss。
  • global_aux：fe 在本 stage 的 16 张卡之间汇总，并在 64 次之间累计；到最后一次时覆盖整个 global batch，8.4M token。
  • DSV3 bias：64 次的计数累加，步末在本 stage 的 TP × DP × CP 之间求和，覆盖 8.4M token。
  • PP 下所有汇总只在本 stage 内做；EP 不参与这些统计；TP 两张卡上的 bias 永远一样。

5DSV3 expert bias

  • 是 buffer，不是参数，没有梯度，任何 loss 都改不了它。
  • 每步：各卡累计每个 expert 分到的 token 数 → 步末跨 TP × DP × CP 求和 → 高于平均的减 0.001，低于平均的加 0.001。每层各自更新。
  • 只有相对大小有用：所有 b 一起加同一个数，不改变路由。

为什么 |b| 的健康上限是 1

分数 s 在 0 到 1 之间。两个 expert 的 b 差一旦超过 1，b 低的那个对任何 token 都赢不了。例：A 的 s = 0.9、b = 0；B 的 s = 0.1、b = +0.85。B 的选人分 0.95 > 0.9，选了 B，虽然 router 更想要 A。

  • 看极差，不看绝对值：DSV3 q3 第 0 层的 b 都在 +11.2 到 +11.7 之间，绝对值很大，极差只有 0.5，问题不大。
  • 整体漂移：按符号更新不是零和的。多数 expert 略低于平均、少数远高于平均时，加的总量大于减的，整层一起往上漂。
  • 病态：b 远大于 1 时，分数接近 0 的 expert 也会被选上，选上后权重又接近 0，等于浪费名额。MaxVio 看起来很好，其实是 bias 在硬撑。
  • 固定步长的局限：E2X 底座的 |b| 最大值 q1 1.73 → q2 4.19 → q3 7.03。每步只能挪 0.001，追不上就会一直偏。这正是 QBK3 要解决的问题。

6Quantile Balancing：QB、QBX、QBK3

共同的想法：不再按固定步长慢慢调门槛，而是每个 step 直接算出"让每个 expert 正好分到平均份额"的门槛。这个门槛是一个分位数，所以叫 quantile balancing。三种实现的区别在门槛加在哪里，以及跨卡怎么合并。

QB（Megatron 自带）

记号（每层各自做）：zte 是 token t 对 expert e 的 logit；k 是每个 token 选几个；E 是 expert 数；T 是一个 micro-batch 的 token 数；C = T·k/E 是每个 expert 的目标 token 数。

  1. 路由：每个 token 选 z − β 最大的 k 个，β 用上一步算好的。
  2. αt：同一排序里第 k+1 名的值，也就是落选的选项里最好的那个。
  3. 新门槛：每个 expert 在这批 token 上取 margin = z − α 的第 C+1 大值。
  4. 步末：对所有 micro-batch、所有 DP rank 取平均，减去均值（居中），写回 β，下一步用。评测时 β 固定。
βe：expert 的门槛αt：token 的门槛
有几个每层每个 expert 一个（E2X 每层 512 个）每层每个 token 一个
含义expert 的"入场价"，越热门越高这个 token 落选选项里最好的分数
什么时候算每个 step 一次每次 forward
存不存存，跟着 checkpoint 走不存，用完就扔
用途路由只用来算新 β

没有"整层一个"的门槛：所有 expert 减同一个数，每个 token 的排序都不变，什么都没改变。也因为这样，第 4 步可以放心减去均值。

为什么取 margin，而不是原始 logit

margin = "这个 token 想要 e，比它落选的头号选项高出多少"。只看原始分数，会把"也很想要别的 expert"的 token 算进来。

3 个 expert，选 1 个zAzBzCα（第 2 名）A 的 margin
token 10.91.51.21.2−0.3
token 20.60.0−0.20.0+0.6

按原始分数，token 1 对 A 更积极（0.9 > 0.6）；但它有 B、C 两个更好的选项，根本不会来抢 A。按 margin，token 2 才是 A 的真正候选。

一个 expert 的门槛怎么定

"正好 C 个"只是近似

  • 只在 α 不变时成立。512 个 β 一起变，每个 token 的 α 也跟着变。对本来没选上的 expert，要挤掉的是第 k 名，比第 k+1 名的 α 更高，判据偏宽。
  • 新 β 用在下一批 token 上，只能做到统计意义上的均衡。
  • 这是对偶问题上的坐标下降，每步修正一次。我们的玩具模拟：64 个 expert 选 4 个，每步一批新的高斯 logit，MaxVio 第一步从 8.8 降到 0.44，之后稳定在 0.15–0.2。

放到 E2X 里：E = 512，k = 16，一个 micro-batch 是 1 条 32K 序列，所以 T = 32,768、C = 1,024，每条序列取第 1,025 大的 margin。一个 step 64 条序列，β 每步更新一次。

QBX：全局精确分位数（我们的补丁）

只改第 4 步：QB 是"每个 micro-batch 的分位数取平均"，QBX 是"所有 micro-batch、所有卡的 margin 合在一起取分位数"。三种做法都要跨卡同步，因为 β 必须在所有卡上相同；区别在同步的是什么。

平均为什么不等于全局

某个 expert，两个 micro-batch 各 4 个 token，每个 micro-batch 的目标是 1 个，全局目标是 2 个。

margin本地第 2 大
micro-batch 1（这条序列很爱用它）0.9, 0.8, 0.7, 0.60.8
micro-batch 2（这条序列基本不用它）0.2, 0.1, 0.0, −0.10.1

QB：β = 平均 0.45，8 个 token 里 4 个过线，是目标的两倍。QBX：8 个合起来取第 3 大，β = 0.7，正好 2 个。序列之间对同一个 expert 的偏好差得越多，QB 偏得越厉害；我们一个 micro-batch 就是一条序列，代码、中文、数学之间差别很大。

QBX 的具体设置
  • Megatron：share/megatron-lm-80781ab0ab-qbx2（改了 router.py、moe_utils.py、finalize_model_grads.py 三个文件）；环境变量 MOE_QB_EXACT=1。命令行参数和 QB 完全一样。
  • 直方图窗口：中心 ± 2.0 logit，255 格，每格约 0.016。格数取奇数：每个 token 都有一个 margin 正好落在中心上，偶数格时它落在格子边界，读数会偏高约 0.3 格（256 格的 run 已删掉重跑）。
  • 落在窗口外的 expert 退回用平均值，并截到窗口边界；q2 结束时每步有 4–16 个（共 11,776 个 router × expert 组合）。
  • 要求 TP = CP = 1。

QBK3：完全按 Kimi K3

K3 是月之暗面的 Kimi K3。QBK3 按 K3 技术报告（2.3.3 节、附录 C / D）和他们在 HF 上公开的推理版 gate 代码实现（训练代码没有公开）。Runlong 核对后发现 QBX 并不是 K3 的做法，所以重写了这一版。

路由完全不动

仍然是 DSV3：按 σ(z) + b 选，权重用不带 b 的 σ(z)。只换了 b 的更新规则，所以可以直接替换现有的 router。

一步到位，没有步长

每步直接把 b 设成全局分位数算出来的值，再减去均值。DSV3 每步最多挪 0.001，QBK3 没有步长要调，默认也不用 EMA。

范围天然有界

σ 在 0 到 1 之间，所以"还差多少 bias"一定落在 [b_min − 1, b_max + 1] 里。1000 格覆盖全部，不会有值落在范围外。

切分无关、代价小

每张卡只记自己的 token，计数相加后逐位相同，TP、CP 都能开。代价约 1% 的 step 时间，显存多 33–45 MiB。

每个 step 一次，覆盖整个 global batch

αi = (si + b) 里第 k+1 大的值
rij = αi − sij（expert j 要挤进 token i 的前 k 名还差多少 bias：bj > rij 就会被选中）
b̂j = 第 ⌈m·k/E⌉ 小的 r·j（从直方图读，格内线性插值）
b = b̂ − mean(b̂)，下一步生效

  • 启动瞬态：没有 LR warmup 时，开头几十步 MaxVio 约 11–15。review 认为是 router 在漂移，不是方法本身的问题，所以另开了 QBK3_WU（加 1% warmup）。
  • 反应速度：合成测试里（router 不断漂移，40 步，从 b = 0 开始），第 8 步以后 QBK3 的 MaxVio 是 0.20，DSV3 按 ±0.001 更新的是 5.6。固定步长从 0 开始本来就追不上，所以这只说明 QBK3 反应快，不代表长时间训练里的差距。
  • 和 K3 原版的不同：我们只搬了均衡方法，结构还是 E2X（512 选 16，1 个 shared，× 2.5）。
  • review：Runlong 让 22 个 agent 审过，没有严重或重要的缺陷（share/megatron_qbk3_tests/REVIEW_REPORT.md）。

现状（11-09）：生产用 E2X + QBK3。59B-A4B 的 de-risk 默认就是 QBK3，PROD_LR_FIT 的 41 个 run 也全是 QBK3；461B 的脚本仍默认 DSV3。选 QBK3 主要是工程原因：没有要调的超参数，bias 不漂，能开 CP，推理框架直接能用。

7router 的优化器与 LR

  • AdamH：Adam 更新，但把整个 router 权重投回固定半径的球面（hyperball），范数不会变大。MuonH 主体的默认。
  • AdamW：普通 AdamW，范数可以自由变化。

挡住 logit 变大的是 hyperball，不是 aux loss

z = Wr·x，x 前面有 norm。只要 router 用 AdamH，Wr 就长不大，logit 也长不大。E2X 上的证据（q2 训练结束时）：

组最大 |logit|pinned
所有 AdamH 的组（底座、只用 bias、QB、QBX、QBK3……）约 16–18≤ 0.2%
router 改用 AdamW，LR × 0.1965.24.26%
每一行单独做 hyperball（约束更紧）16.10.12%
  • 宽模型上 router 会崩：L24 h4096 的格子上，MuonH + softmax router 在 h ≥ 3072 时第 50 步负载均衡 loss 就到 15（上限 16 = 所有 token 选同样的 expert）。gate 换 AdamW 没用；router LR 降到 × 0.25 修好了。Runlong 的候选规则：router LR 倍数 = min(1, 2048 / h)。PROD_LR_FIT 里有 router LR × 0.25 / 0.5 / 1 在 h2048 和 h4096 上的对比。
  • 老 ladder 的结论：DSV3 + AdamH + LR × 1 时 bias 一路涨；LR 降到 × 0.19 就健康；AdamW gate 会把分数卡在 1（见第 9 节）。

8健康指标怎么看

Boxiang 的 router_health.py 每 100 步记一次。9 个指标回答两个问题：expert 之间分活均不均，router 有没有失控。

指标量什么健康标准注意
MaxVio（层平均 / 最差层）最忙的 expert ÷ 平均 − 1逐渐下降最差层要单独看，问题常藏在第 0 层
dead expert (%)负载不到平均 10% 的 expert 占（层数 × E）的比例0换算成个数更直观，见下
|bias| 最大所有层、所有 expert 的 |b| 最大值< 1看同层极差；QB / QBX 的 β 不统计
logit 饱和 (%)|z| > 4 的比例不是判据包括 z < −4（明确不选），无害
z > +4 (%)只算正向饱和< 5%softmax 下无意义
top-8 pinned (%)每个 token 最大的 8 个 logit 里 z > 4 的比例< 5%E2X 选 16 个，这个指标也只看 8 个
最大 |logit|所有层里最大的 |z|看趋势只是一个极值
gate 更新幅度router 权重这一步的相对变化只作参考末期会被 bf16 精度量化

统计范围：MaxVio、dead、gate 更新幅度覆盖一整个 step 的所有 token；logit 相关的四个只看 rank 0 的第一个 micro-batch。

负载：MaxVio 和 dead

  • 一个 step 221 个 token。128 选 8 时平均每个 expert 131,072 个，512 选 16 时 65,536 个。MaxVio = 0.17 表示最忙的 expert 分到 1.17 倍。
  • 为什么重要：expert 并行时，所有卡都要等最忙的那张，它同时决定速度和显存。
  • dead expert 拿不到梯度就不会变好，会越来越冷。换算：老 q0 是 12 层 × 128 = 1,536 个，0.0651% = 1 个；E2X q2 是 24 × 512 = 12,288 个，0.17% ≈ 21 个。

logit：z > +4 是坏信号，z < −4 无所谓

  • z < −4 是"明确不要这个 expert"。大部分 expert 本来就不该被选，饱和也不损失什么。所以"logit 饱和"在 40–75% 本身不算坏。
  • z > +4 / pinned 是被选中的 expert 分数钉在 1：几个 σ 都约等于 1，归一化后权重几乎一样，router 既分不出高低，梯度也传不进去。
  • 128 选 8 时 pinned ≈ 16 × (z > +4)，因为 z > 4 的几乎都在前 8 名里，分母从 128 换成 8。实测 0.55% × 16 ≈ 8.9%，对得上。
  • "硬分类器"指 router 对每个 token 都极其确定，不是分不了类。坏处有三个：早期的分配被锁死；选中的几个权重失去区分度；DSV3 里选谁变成由 bias 决定。
  • 最大 |logit| 只能看趋势：它说明 router 权重的尺度在变大；被选中的是否变硬，要看 z > +4 和 pinned。

Boxiang 预设的判据（dsv3/DESIGN.md 第 3 节）：z > +4 和 pinned < 5%；dead = 0；|b| < 1；MaxVio 逐渐下降；gate 更新幅度只作参考。

10常见误解

说法对不对实际是
QB 的门槛是整层一个，或者每个 token 一个都不对β 每个 expert 一个；α 每个 token 一个，只是中间量
QB 不需要全局同步不对β 必须在所有卡上相同，QB 也做 all-reduce；区别在同步的是分位数还是直方图
QBX 就是 K3 的做法不对QBX 只借了 K3 的全局合并，门槛仍加在 logit 上
QBX 和 QBK3 一样一半对合并方式一样；门槛加的位置不同，挤走的 token 也不同
权重是把 z 归一化不对先过 sigmoid，再在选中的 k 个里归一化，再乘 2.5
QB 没有 aux loss 却让 pinned 变好前提不成立QB 的 pinned 和底座一样；pinned 由 hyperball 挡住
QB 的负载均衡一直比底座好只有前期对后期底座 0.4–0.6，QB 约 1.4
z < −4 的饱和是坏事不对只是明确不选；坏的是 z > +4 / pinned
|b| 大就是病态不一定看同层极差；整层一起漂不影响路由
