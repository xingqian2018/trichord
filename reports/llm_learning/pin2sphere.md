## 0. 背景知识

后面反复用到四个量。前三个衡量 "一组数有多大"，第四个 fan_in 是一个输出读多少个输入。

| 量             | 算法                                   | 用在哪                                                                      |
|----------------|----------------------------------------|-----------------------------------------------------------------------------|
| L2 范数        | √(平方和)                              | 一个向量                                                                    |
| Frobenius 范数 | √(所有元素的平方和)                    | 一个矩阵或一块张量。等于把它拉平成向量后的 L2 范数，不是谱范数              |
| RMS（均方根）  | √(平方和 / N)，N 是元素个数            | 向量、矩阵都可以                                                            |
| fan_in         | 一个输出是多少个输入的加权和，这个个数 | 线性层的权重。例如权重是 3 × 4（3 个输出，每个输出读 4 个输入），fan_in = 4 |

写成公式（x 有 N 个元素）：

```math
\lVert x \rVert = \sqrt{\sum_{i=1}^{N} x_i^2}, \qquad \text{RMS}(x) = \sqrt{\frac{1}{N}\sum_{i=1}^{N} x_i^2} = \frac{\lVert x \rVert}{\sqrt{N}}
```

换算只有一条：**RMS = 范数 / √N**。

例子：`[3, 1, 1, 1]` 的平方和是 12，范数是 √12 = 3.464，N = 4，RMS 是 3.464 / 2 = 1.732。

**RMSNorm** 是网络里的一种归一化层，作用在前向的激活值上：

```math
y = \frac{x}{\text{RMS}(x)} \odot g
```

- 对一个 token 的向量（长度 = 维度）算 RMS 并除掉。之后 RMS 是 1，范数是 √维度。
- `g` 是可训练的增益：每个维度一个数，所有 token 共用，初始全是 1。

## 1. Hyperball 机制

受约束的矩阵每一步做两件事：先走一步，再把范数缩回走之前的值。

<!-- cols box -->

第 1 步，走一步。η 是学习率，U 是更新方向，W′ 是走完之后的权重：

```math
W' = W - \eta \, \frac{\lVert W \rVert_F}{\lVert U \rVert_F} \, U
```

<!-- col -->

第 2 步，缩回走之前的范数：

```math
W \leftarrow W' \cdot \frac{\lVert W \rVert_F}{\lVert W' \rVert_F}
```

<!-- /cols -->

更新方向 U 有两种算法。G 是这一步的梯度。

<!-- cols box -->

**MuonH**：M 是动量，μ 是动量系数，NS₅ 是 5 次 Newton-Schulz 迭代（把矩阵正交化）。

```math
M \leftarrow \mu M + G, \qquad U = \text{NS}_5(\mu M + G)
```

<!-- col -->

**AdamH**：M 是梯度的滑动平均，V 是梯度平方的滑动平均，β₁、β₂ 是滑动平均的系数，t 是步数。带帽子的是除掉起步偏差之后的值。

```math
M \leftarrow \beta_1 M + (1 - \beta_1)\, G, \qquad V \leftarrow \beta_2 V + (1 - \beta_2)\, G \odot G, \qquad \hat{M} = \frac{M}{1 - \beta_1^t}, \qquad \hat{V} = \frac{V}{1 - \beta_2^t}, \qquad U = \frac{\hat{M}}{\sqrt{\hat{V}} + \epsilon}
```

<!-- /cols -->

- **范数是整个矩阵的 Frobenius 范数**。一个矩阵一个球面，不分行，不分列。
- **步长是相对的**：第 1 步保证每一步 ‖W′ − W‖ / ‖W‖ = η。
- **半径没有规定值**：第 2 步缩回的是这一步之前的范数，一路追溯回去就是初始化时的范数。初始化时乘上去的任何系数都会被永久保留（见 §3）。

## 4. 深度系数是什么

深度系数是 1/√(2L)，L 是层数。整个网络用同一个数：59B（L = 48）是 0.102，461B（L = 94）是 0.073。它乘在往残差流里写的矩阵上：注意力输出投影、shared expert 和第 0 层 dense 的 fc2、latent 投影（出）。V1 还按名字乘在路由 expert 的 fc2 上，这个矩阵不直接写残差流，V2 去掉了。代码只按总层数算一次，不看是第几层（`scaling_ladder/hyperp/init.py`）：

```python
residual_scale = 1.0 / math.sqrt(2.0 * num_layers)
scale = residual_scale if is_residual else 1.0
```

### 4.1 原则：残差流的幅度不随层数增长

1. 每层往残差流写两次（注意力一次，MLP 一次），L 层共写 2L 次。
2. 每个分支读的是归一化之后的输入，所以每次写进去的幅度差不多，设 RMS 为 σ。
3. 2L 次写入大致互不相关，相加时是方差相加：总方差约 2L·σ²，总幅度约 √(2L)·σ。层数越多，残差流越大。
4. 每次写入乘 1/√(2L)，总方差回到 σ²，和层数无关：

```math
\mathrm{Var}\left(\sum_{i=1}^{2L} \frac{b_i}{\sqrt{2L}}\right) = 2L \cdot \frac{\sigma^2}{2L} = \sigma^2
```

- **为什么开根号**：不相关的量相加，加的是方差，幅度按 √ 增长。如果每次写入完全同向，就要除以 2L。
- **为什么全网络统一**：2L 次写入在统计上是对称的，没有哪一层比别的层更该缩小。系数管的是最后的总和，不是某一层。

### 4.2 各家的做法

| 做法                     | 在哪里缩放                                                                 | 训练中会不会变                                  |
|--------------------------|----------------------------------------------------------------------------|-------------------------------------------------|
| Megatron、GPT-2 的初始化 | 初始化时乘在输出矩阵上：`scaled_init_method_normal`，std / √(2·num_layers) | 会，权重可以长回来                              |
| ArchScale                | 前向里每个分支除以 √(2L)（开关 `depth_mup`）                               | 不会                                            |
| 我们                     | 初始化时乘在输出矩阵上                                                     | 不会：hyperball 保持范数，效果和 ArchScale 相同 |
| Muse                     | 没有深度系数，矩阵不缩小。分支输出先过 post-norm，再经过可学的残差门控     | 可学                                            |
| P2S 文档                 | 没提。所有矩阵按 RMS = 1/√fan_in 钉，和层数无关                            | —                                               |

ArchScale 的 depth-μP 除了控制幅度，还让最优学习率可以在不同深度之间迁移：用小模型定的学习率，可以直接用到层数更多的模型上。

Muse 的残差门控（`MuseSparkResidualGate`），w 每层每个分支 8,192 个，一个通道一个，可学：

```math
\beta = \sigma\!\left(\frac{w}{T}\right), \qquad \alpha = \sqrt{\left(1 - \beta\right)\left(1 + \beta\right)}, \qquad h \leftarrow \alpha \cdot h + \beta \cdot b
```

α² + β² = 1，所以残差 h 和分支 b 的 RMS 都是 1、两者不相关时，加完之后残差流的 RMS 还是 1。层数多少都不会让残差流变大，每个通道还能自己决定分支占多少。

## 5. 外部：Muse Spark Open（从权重里量出来的）

### 5.1 结构

- 62 层语言层**全部是 MoE**，第 0 层也是；没有 dense 层，没有 shared expert。
- 每层 256 个 expert，每个 token 选 8 个。
- hidden 8,192；expert 工作在 4,096 维的 latent 里（`pre_expert_proj` / `post_expert_proj` 进出）。
- expert 是普通 SwiGLU：`act_fn(gate_proj(x)) * up_proj(x)`，激活是 silu。gate、up、down 都是 4,096 × 4,096 的方阵。
- 周边：expert 之前有一个去均值的 RMSNorm；每个 expert 之后有 post-norm；残差分支用学出来的门控缩放。

### 5.2 约束

| 参数                                  | 球面单位             | 范数                                                                          |
|---------------------------------------|----------------------|-------------------------------------------------------------------------------|
| q、k、v、输出投影                     | 各自整块矩阵         | 元素 RMS = 2^-7.5 = 0.005524                                                  |

| token embedding                       | 每一行               | √32 = 5.657，查表后紧接一个无增益的 RMSNorm，每个 token 以 RMS = 1 进入残差流 |

- 总量：623 个张量、99.755 % 的元素，在 472,114 个球面上。

### 5.3 Muse 也没解决的

- **第一个 MoE 层的饥饿还在**，只是被 "按选中次数均衡" 盖住了：第 0 层 10–13 % 的选中名额权重不到 1 %，第 1 层 2.7–7.2 %；第 0 层 256 个 expert 里有 52–54 个只靠 bias 才被选中。
- 它的 router bias 是很慢的、去均值的符号步进，不是每步按分位数算。
- 浅层的 latent 投影是秩亏的（第 0–19 层，4,096 个方向里只有 817–3,762 个在用）；每层有一个 "sink" 通道承载约 75 % 的 expert 归一化输出。会话的解读：模型自己绕着归一化重建了一条幅度通路。【推断】

## 基本数字（59B）

| 项目              | 59B                                              |
|-------------------|--------------------------------------------------|
| hidden h          | 2,048                                            |
| latent 维度       | 1,024                                            |
| 路由 expert       | 512 个，每个 768 个神经元，SwiGLU                |
| 每个 token 选几个 | 16 个                                            |
| shared expert     | 1 个，768 个神经元，读写都是 h                   |
| 注意力            | 32 个 q head，4 组 k、v，每个 head 128 维        |
| 层数              | 48：第 0 层是 dense MLP，第 1–47 层是 latent MoE |

## 一层里的残差流

每层往残差流 h 写两次，都是先归一化、再算分支、再加回去（pre-norm）：

```
h ← h + 注意力( RMSNorm(h) )
h ← h + MoE( RMSNorm(h) )
```

残差流本身不归一化，只有每个分支的输入归一化。分支的输出原样加回去，所以每个分支最后那个矩阵的大小，就是它往残差流里写的幅度。

## MoE 分支内部

一个 token 进来时是过完 RMSNorm 的 2,048 维向量 x：

```
                    x (2,048)
        ┌─────────────┼──────────────────────┐
        │             │                      │
     router      latent 投影（进）       shared expert
   512 × 2,048     1,024 × 2,048       fc1 1,536 × 2,048
        │             │                 SwiGLU → 768
   选 16 个 expert   z (1,024)          fc2 2,048 × 768
   和各自的权重 p     │                      │
        │        发给选中的 16 个 expert      │
        │             │                      │
        │     每个 expert：                  │
        │       gate、up 各 768 × 1,024      │
        │       silu(gate) ⊙ up → 768        │
        │       fc2 1,024 × 768 → 1,024      │
        │             │                      │
        └──────► 加权求和 Σ p·y (1,024)       │
                      │                      │
                  fc2_norm（RMSNorm，1,024）  │
                      │                      │
              latent 投影（出）2,048 × 1,024  │
                      │                      │
                      └──────── + ───────────┘
                                │
                         MoE 输出 (2,048) → 加进残差流
```

router 和 shared expert 读的是原始的 2,048 维 x，不走 latent。

## 路由

1. **打分**：logits = router · x，512 个数，每个过 sigmoid，得到分数 s。
2. **选 expert**：按 s + `expert_bias` 取最高的 16 个。`expert_bias` 只用来选，不进权重；它不靠梯度训练，每步结束时按负载更新。
3. **权重**：选中的 16 个 s 先归一化成和为 1，再乘 2.5，所以 16 个权重加起来是 2.5。

## 哪个矩阵写进残差流

| 路径          | 最后一个矩阵         | 输出去哪                            | 深度系数                   |
|---------------|----------------------|-------------------------------------|----------------------------|
| 注意力        | 注意力输出投影       | 直接加进残差流                      | 乘                         |
| 路由 expert   | 路由 expert 的 fc2   | 加权求和后进 `fc2_norm`，尺度被抹掉 | V1 按名字匹配乘了；V2 不乘 |
| 路由 expert   | latent 投影（出）    | 直接加进残差流                      | 乘                         |
| shared expert | shared expert 的 fc2 | 直接加进残差流                      | 乘                         |
| 第 0 层 dense | dense 的 fc2         | 直接加进残差流                      | 乘                         |

路由这一支写进残差流的幅度，由 `fc2_norm` 的增益和 latent 投影（出）决定，和路由 expert 自己 fc2 的大小无关。

## 为什么叫 latent

- **expert 在窄空间里算**：token 进 expert 之前先压到 1,024 维，expert 读写的都是 1,024 维。每个 expert 的参数是 1,536 × 1,024 + 1,024 × 768 ≈ 236 万；直接读写 h 的话是 1,536 × 2,048 + 2,048 × 768 ≈ 472 万，正好一半。
- **通信减半**：token 经 all-to-all 发到 expert 所在的 GPU，发的是 1,024 维向量。压缩在发送前做一次，回来后还原一次。
- **代价**：所有 expert 共用同一对投影，只能看到 x 被压到 1,024 维之后的那部分信息。

整层路由 expert 的参数：512 × 236 万 ≈ 12.1 亿，47 层约 568 亿；其余来自注意力、embedding、head 等。【推导】
