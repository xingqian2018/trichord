## 2. 正在做的 P2S 对齐版本

Runlong 在看完 `pin2sphere.md` §7 的对照后要求：半径按公式固定，router 按文档，gate / up / down 都分开，放在本地另一个代码树里。

### 2.1 两条线

- **MR !36（草稿）**：只有 `--hyperp-split-gate-up-spheres`，目标分支 ultra-prod。只跑过 CPU 测试，没有 GPU 冒烟，没有标 ready。
- **本地代码树** `share/megatron-lm-ultra-prod-a6eb662-p2s`：没有 remote，没有推送。下面四个开关都默认关。

| 开关                             | 做什么                                                                    |
|----------------------------------|---------------------------------------------------------------------------|
| `--hyperp-fixed-radius 1`        | 每个球面缩到公式定的绝对半径：每行范数 1；路由 expert 是 1/√(选中数)      |
| `--hyperp-router-rows 1`         | router 每个 expert 的向量一个球面，半径 1（`--hyperp-router-row-radius`） |
| `--hyperp-split-gate-up-spheres` | gate、up、down 三个球面                                                   |
| `--hyperp-dense-blocks`          | 第 0 层 dense 切成 9 块，每块再分 gate / up / fc2                         |

- 残差输出矩阵的 1/√(2L) 默认保留（`--hyperp-fixed-radius-depth-scale`）。
- 路由 expert 除以 √(选中数) 的依据是 Muse 的实测（`pin2sphere.md` §5.2）。
- router 半径用的是 1。Muse 实际是 √(h/E)：q0 时正好是 1，q1 1.22，q2 1.41，q3 1.58，59B 2.0。

### 2.2 开了之后和文档还差什么【推导】

按 `pin2sphere.md` §7.2 的表逐项看，四个开关全开之后仍然不同的有：

- embedding 仍然用 AdamW，不上球面。
- 仍然没有坐标裁剪。
- 输出 head 仍然是整块一个球面。
- 深度系数 1/√(2L) 仍然在（文档和 Muse 都没有）。

### 2.4 顺带确认的几件事

- Muse 没有 dense 层，所以它没有 "切块" 这回事，单位就是 expert。
- 第 0 层改成 17 个 shared expert 不建议：功能上就是一个 dense MLP，而且 Megatron 把 shared expert 建成一个合并的矩阵。
- 切块、q/k/v 分开、gate / up 分开都只支持没被 TP 切分的参数（TP = 1，否则报错）。59B 是 TP 1 / PP 1 / CP 1 / EP 16，461B 的脚本是 TP 1 / CP 4 / EP 16 / PP 4，都不受影响。
- 切块不改模型、前向、checkpoint 和推理，只改优化器怎么分组。
